# 1.1 什么是因特网

本书选择“公共因特网”这种特定的计算机网络作为讨论计算机网络及其协议的主要载体。计算机网络它可以很小，比如家里的几台设备通过路由器连起来；也可以很大，比如一个大学校园里的所有计算机组成的网络。而本书聚焦“公共因特网”，特指那个全球性的、由无数个较小的网络（包括家庭网络、公司网络、学校网络、政府网络等）互相连接而成的巨大网络。

我们有**两种方式**描述因特网的具体构成：

- 围绕因特网的[具体构成](#111-具体构成描述)(基本硬件和软件组件)
- 围绕为分布式应用[提供服务](#112-服务描述)的联网基础设施

## 1.1.1 具体构成描述

![因特网的一些部件](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-1.webp)

因特网是一个世界范围的计算机网络。这个网络里面的设备称为**主机(host)**或**端系统(end system)**。

端系统通过**通信链路(communication link)**和**分组交换机(packet switch)**连接到一起。

端系统通过**因特网服务提供商(Internet Service Provider, ISP)**接入因特网。我们将在[网络核心](#13-网络核心)中更为详细地考察 ISP 及其互联的情况。

端系统、分组交换机和其他因特网部件都要运行一系列**协议(protocol)**，这些协议控制因特网中信息的接收和发送。

### 端系统

网络中的计算设备称为**主机(host)**或**端系统(end system)**。当一个端系统向另一个端系统发送数据时，会将数据分段并添加首部字节，形成称为**分组(packet)**的信息包。这些分组通过网络发送到目的端系统后，会被重新组装成原始数据。

分组在网络中传输时，经过的通信链路和分组交换机序列称为**路径**(route 或 path)。

### 通信链路

通信链路是由不同类型的物理媒体组成的传输通道，包括：

- 有线媒体：同轴电缆、铜线、光纤
- 无线媒体：无线电频谱

链路的传输速率以比特/秒(`bit/s`或`bps`)度量。详细内容将在[1.2 节](#12-网络边缘)中介绍。

### 分组交换机

分组交换机是网络中的设备，它的工作是接收数据包(分组)，然后将这些数据包转发到正确的方向，让它们最终能到达目的地。它的两种主要类型

1. **路由器(router)**：决定数据包的"城市间路线"
2. **链路层交换机(link-layer switch)**：决定数据包在"本地区域"内的路线

这两种类型的交换机朝着最终目的地转发分组。链路层交换机通常用于接入网中，而路由器通常用于网络核心中。

> 既然书上说“路由器通常用于网络核心”，那么我家里面的路由器是干什么的？
>
> 可以这样理解：书上提到的所谓的链路层交换机/路由器都是概念名词，它们是单一功能功能，但是实际的设备可能聚合了多个功能。比如说家用的路由器兼具了路由器和交换器的功能。它既负责转发家庭网络和互联网之间的数据包转发（路由器），也负责家庭网络内部设备通信（交换机）。

### ISP

ISP 的作用：

1. **ISP 提供多种接入方式**：包括家庭宽带、企业网络接入和移动接入等
2. **ISP 不仅服务普通用户，也服务内容提供商**：网站和视频服务器也需要通过 ISP 接入互联网
3. **ISP 有层级结构**：分为较低层和较高层的 ISP

ISP 可以分为较低层和较高层

1. **第一层 ISP(Tier 1)**：

   - 全球性骨干网络提供商
   - 直接互联，无需付费即可交换流量
   - 覆盖范围最广

2. **第二层 ISP(Tier 2)**：

   - 区域性或国家级 ISP
   - 与一些 ISP 对等互联，向一级 ISP 付费购买传输服务

3. **第三层 ISP(Tier 3)**：

   - 本地 ISP
   - 主要向最终用户提供服务
   - 从更高层 ISP 购买接入服务

主要运营商示例：

- **中国**：中国电信、中国移动、中国联通、中国广电、教育网(CERNET)
- **美国**：AT&T、Verizon、Comcast(Xfinity)、T-Mobile

### 协议

协议是控制网络通信的规则集合。主要协议包括：

- TCP(传输控制协议)
- IP(网际协议)
- HTTP(网页访问)
- SMTP(电子邮件)

这些协议由 IETF(因特网工程任务组)制定，以 RFC(请求评论)的形式发布。关于[[RFC阅读/README|RFC]]我也整理了一些笔记。

### 实际应用示例

1. **日常上网场景**

   - 手机通过 WiFi 或 4G 连接网络
   - 经家用路由器或基站转发
   - 通过 ISP 访问目标服务器
   - 使用相应协议(如 HTTP)传输数据

2. **跨国视频会议场景**

   - 多个端系统通过不同 ISP 接入
   - 数据经过多个路由器转发
   - 经过多个国家的骨干网络
   - 使用实时传输协议保证通信质量

## 1.1.2 服务描述

除了像上面[具体构成描述](#111-具体构成描述)这样描述互联网，我们还可以从分布式应用的角度描述它。

### 应用程序类型

现代因特网承载着丰富多彩的应用：

- 传统应用：电子邮件、网页浏览
- 即时通讯：微信、QQ、Telegram
- 流媒体服务：网易云音乐、抖音、Netflix
- 在线游戏：王者荣耀、英雄联盟
- 位置服务：高德地图、美团外卖
- 视频会议：腾讯会议、Zoom

这些应用有个共同特点：它们都是**分布式应用程序(distributed application)**。就像一场多人协作的游戏，需要多个玩家（端系统）互相配合才能运行。

简单拓展一下，这里所谓的“互相配合”可以分成两种模式：

1. 客户端-服务器模式 (Client-Server Model)
   - 网页浏览: 你的浏览器（客户端）向网站服务器发送请求，要求获取某个网页。服务器收到请求后，找到对应的网页文件，把它发送回你的浏览器。浏览器再把接收到的文件“画”成你看到的网页。这一来一回，就是一次配合。
   - 发微信: 你的微信 App（客户端）把你输入的消息发送给腾讯的微信服务器。服务器收到后，查找你的好友，再把消息转发给你好友的微信 App（另一个客户端）。这个过程中，你的手机、腾讯服务器、你好友的手机，三者就在“配合”完成消息的传递。
2. 对等模式 (Peer-to-Peer, P2P Model)
   - 比如某些在线游戏的部分数据同步，或者一些文件共享工具，数据可以直接从一个用户的设备传输到另一个用户的设备，不完全依赖中心服务器。

### 应用程序的运行方式

有趣的是，这些应用程序只在端系统（如你的手机、电脑）上运行，而不在网络中间的设备上运行。打个比方：

- 端系统就像游戏玩家，负责运行游戏程序
- 分组交换机就像快递员，只负责传递消息
- 快递员虽然能加快信息传递，但不会参与游戏本身

#### 套接字(Socket)接口

为了让应用程序能够相互通信，因特网提供了一个叫"**套接字接口(socket interface)**"的工具。这就像是一个通用的快递单格式：

- 寄件人必须按规定填写收件地址
- 快递公司按照单号进行派送
- 确保包裹准确送到收件人手中

> 提示：在[[CS3611/第2章 应用层|第 2 章]]中，我们会详细介绍套接字接口的工作原理。

#### 实际应用举例

想象你正在和朋友打游戏：

1. 你在手机上操作英雄/开枪射击（端系统 A）
2. 游戏数据通过网络传输（分组交换机转发）
3. 你朋友的手机收到数据并显示（端系统 B）
4. 整个过程按照套接字接口规则进行通信

这样的设计确保了所有网络应用能够可靠地在全球范围内运行，让我们能够享受丰富的网络服务。

## 1.1.3 什么是协议

> **协议(protocol)**定义了在两个或多个通信实体之间交换的报文的格式和顺序，以及报文的发送/接收或其他事件所采取的操作。

![人类协议和计算机网络协议](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-2.webp)

### 协议的三个关键要素

1. **格式**：规定数据如何组织
2. **顺序**：定义通信步骤的先后次序
3. **动作**：收到消息后该做什么

> 协议 Protocol 和套接字 Socket 都是在规定数据的格式，那么它们有什么区别？或者说 Socket 是一种协议吗？
>
> Socket 并不是一种协议。它们是两个层面上的概念，但是 Socket 是应用程序使用协议的“入口”或“工具箱”。等到第二章了解了“应用层”，实际用 python 进行套接字编程的时候更好理解。

### 期末复习：协议三要素

#了解

我们以生活中最常见的HTTP协议为例来看三要素分别是什么：

#### 1. 格式 - 数据如何组织

HTTP消息有固定的格式结构：

**请求格式：**

```
GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Accept: text/html

[可选的请求体]
```

**响应格式：**

```
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1234

<html>网页内容</html>
```

- 第一行：请求行/状态行
- 中间部分：头部字段
- 空行分隔
- 最后：消息体

#### 2. 顺序 - 通信步骤

HTTP遵循严格的请求-响应顺序：

```
客户端 → 服务器：发送HTTP请求
客户端 ← 服务器：返回HTTP响应
```

**具体步骤：**

1. 客户端建立TCP连接
2. 发送HTTP请求
3. 服务器处理请求
4. 返回HTTP响应
5. 关闭连接（HTTP/1.0）或保持连接（HTTP/1.1）

#### 3. 动作 - 收到消息后的行为

**服务器收到请求后的动作：**

- `GET`请求 → 返回指定资源
- `POST`请求 → 处理提交的数据
- `404`错误 → 返回"页面未找到"

**客户端收到响应后的动作：**

- `200 OK` → 显示网页内容
- `301重定向` → 跳转到新地址
- `404错误` → 显示错误页面

#### 4. 完整流程

当你在浏览器输入网址时：

1. **格式**：浏览器按HTTP格式组织请求
2. **顺序**：先发请求，再等响应
3. **动作**：根据状态码决定显示内容还是报错

这就是HTTP协议如何通过三要素实现可靠的网页通信！

# 1.2 网络边缘

![端系统交互](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-3.webp)

通常把与因特网相连的计算机和其他设备称为端系统，因为它们位于因特网的边缘。而端系统也可以称为**主机(host)**，因为它们容纳(host)应用程序。

主机有时又被进一步划分为两类：**客户(client)**和**服务器(server)**。

客户通常是桌面 PC、移动 PC 和智能手机等，而服务器通常是更为强大的机器，用于存储和发布 Web 页面、流视频、中继电子邮件等。今天,大部分提供搜索结果、电子邮件、Web 页面和视频的服务器都属于大型**数据中心(data center)**。

## 1.2.1 接入网络

考虑了位于“网络边缘”的应用程序和端系统后，我们接下来考虑**接入网**，这是指将端系统物理连接到其**边缘路由器(edge router)**的网络。边缘路由器是端系统到任何其他远程端系统的路径上的第一台路由器。

![接入网](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-4.webp)

### 1. 家庭介入：DSL、电缆、FTTH 和 5G 固定式无线

今天，宽带住宅接入有两种最流行的类型：**数字用户线(Digital Subscriber Line, DSL)**和电缆。

> 与宽带相对的是“窄带”，在 1990s-早 2000s，人们采用拨号上网的方式。拨号上网是通过普通电话线和调制解调器(Modem)连接到互联网的一种方式。用户需要通过电脑的调制解调器拨打互联网服务提供商(ISP)的接入号码，建立临时连接。最高速率通常为 56 Kbps；连接期间会占用电话线，无法同时通话；每次使用需要重新拨号连接，使用完毕后断开。

#### DSL

DSL 利用电话公司现有的本地电话基础设施。

![DSL因特网接入](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-5.webp)

每个用户的 DSL 调制解调器使用现有的电话线（即双绞铜线，将在[1.2.2 节](#122-物理媒介)中讨论它）与位于电话公司的本地中心局（CO）中的数字用户线接入复用器（DSLAM）交换数据。家庭的 DSL 调制解调器得到数字数据后将其转换为高频音，以通过电话线传输给本地中心局；来自许多家庭的模拟信号在 DSLAM 处被转换回数字形式。

家庭电话线同时承载了数据和传统的电话信号，它们用不同的频率进行编码：

- 高速下行信道，位于 50kHz 到 1MHz 频段；
- 中速上行信道，位于 4kHz 到 50kHz 频段；
- 普通的双向电话信道，位于 0 到 4kHz 频段。

这种方法使单根 DSL 线路看起来就像有 3 根单独的线路一样，因此一个电话呼叫和一个因特网连接能够同时共享 DSL 链路。（[1.3.1 节](#131-分组交换)将描述这种频分复用技术。）

而在用户这一侧，电话线连接着一个分频器。分频器把到达家庭的数据信号和电话信号分隔开，并将数据信号转发给 DSL 调制器解调器。在电话公司一侧，数字用户线接入 DSLAM，把数据和电话信号分隔开，然后将数据送往因特网。

#### 电缆

**电缆因特网接入(cable Internet access)**利用了有线电视公司现有的有线电视基础设施。

因特网连接到电缆头端，光纤将电缆头端连接到地区枢纽（光纤节点），然后同轴电缆负责到达各个家庭和各个公寓。整个系统既应用了光纤也应用了同轴电缆，所以它被称为混合光纤同轴(Hybride Fiber Coax, HFC)系统。

电缆因特网接入需要电缆调制解调器(cable modem)，和 DSL 调制解调器一样，它通常是一个外部设备，用过一个以太网端口连接到家庭 PC。(我们将在[[第6章 链路层和层域网]]里面详细的讨论以太网)。而在电缆头端，电缆调制解调器端接系统(Cable Modem Termination System, CMTS)和前面[DSL](#dsl)网络的 DSLAM 的功能类似。

电缆调制解调器将 HFC 网络划分成下行和上行两个信道，通常不对称。

电缆因特网接入的一个重要特征是共享广播媒体。下行和上行信道对于多个家庭是共享的，因此在多个用户同时下载/上传的时候可能出现实际速率大大低于宣称速率。所以需要一个分布式多路访问协议来协调传输和避免碰撞。（我们将在[[第6章 链路层和层域网]]中更为详细地讨论碰撞问题。）

![一个混合光纤同轴接入网](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-6.webp)

#### FTTH

**光纤到户(Fiber To The Home, FTTH)**提供了一条从本地中心局直接到家庭的光纤路径。

![FTTH因特网接入](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-7.webp)

> 我觉得国内，至少上海应该大部分房屋都采用的是 FTTH 这种方案。

光纤分配方案：

- 最简单直接的：直接光纤，从本地中心局到每户设置一根光纤
- 更一般的：中心局的光纤由许多家庭共享，直到相对接近这些家庭的位置，才分为每户一根光纤。这种分配还可以分为：
  - 有源光纤网络(Active Optical Network, AON)，本质上是交换以太网，我们将在[[第6章 链路层和层域网|第6章]]中讨论

# 1.3 网络核心

网络核心，即由互联因特网端系统的分组交换机和链路构成的网状网络。而通过网络链路和交换机移动数据有两种基本方法：[电路交换(circuit switching)](#132-电路交换)和[分组交换(packet switching)](#131-分组交换)。

![网络核心](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-10.webp)

## 1.3.1 分组交换

端系统之间彼此交换**报文(message)**。报文可以包含网络应用需要的任何东西：

- 执行一种控制功能
- 包含数据

为了发送报文，源需要将长报文划分成较小的数据块，称为**分组(packet)**。

在源和目的地之间，每个分组通过通信链路和**分组交换机(packet switch)**传送，主要有**路由器(router)** 和**链路层交换机(link-layer switch)** 两类。

分组以等于该链路*最大*传输速率的速度通过通信链路。比如说分组大小为$L\text{bit}$，链路的传输速率为$R\text{bps}$，则传输该分组需要$L/R\text{s}$的时间。

### 存储转发传输

多数分组交换机在链路的输入端使用**存储转发传输(store-and-forward transimission)** 机制。

![存储转发分组交换](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-11.webp)

在这种机制下，一个分组的前几个 bit 到达路由器后，先被存储起来，直到路由器接收到了这个分组的所有 bit 才会开始向出链路传输（即“转发”）该分组。

![分组交换](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-12.webp)

对于一个分组而言，经过$N$条速率均为$R$的链路组成的路径，端到端时延是$$d_{end-end}=N\frac{L}{R}$$

同样的情景对于$P$个分组，总体时延是$$(N+P-1)\frac{L}{R}$$

### 排队时延和分组丢失

每台分组交换机对于和它相连的每条链路都有一个**输出缓存(output buffer)**，也称为**输出队列(output queue)**，用来存储路由器准备发往那条链路的分组。如果一个到达的分组需要传输到某条链路，但该链路正忙于传输其他分组，该到达分组必须在输出缓存中等待。这种等待就是分组的**排队时延(queuing delay)**。而缓存空间是有限的，假如新的分组到达的时候发现缓存已经满了，就会出现**分组丢失（丢包）(packet loss)**，到达的分组或者已经排队的分组之一将被丢弃。

我们将在[1.4 节](#14-分组交换网中的时延丢包和吞吐量)中更详细地研究排队时延。

### 转发表和路由选择协议

路由器有一个自动配置的内置**路由表(forwarding table)**来决定该将到达的分组向哪条链路进行转发。而这个路由表究竟是如何配置的，我们会在[[第5章 网络层：控制平面|第5章]]深入研究这个配置过程，但是现在我们只要知道因特网具有一些特殊的**路由选择协议(routing protocol)**，用于自动设置这些转发表。

## 1.3.2 电路交换

在**电路交换网络**中，当两个端系统需要通信时，必须在它们之间建立一条专用的端到端连接。网络会为这条连接预留 (reserve) 所需的资源，比如链路上的传输速率（带宽）、交换机里的缓存等。并且，在整个通信会话期间，这些资源是被这条连接独占的，即使暂时没有数据传输，资源也不会被释放给其他连接使用。

电路交换好比去一家需要预订的餐厅，你提前打电话订好位子，虽然麻烦一点，但到了餐厅就能保证有你的专属座位。而分组交换则像去一家不接受预订的餐厅，你不需要提前麻烦，直接去就行，但如果人多，你可能就得排队等位子。

我们最熟悉的电路交换网络就是传统的电话网络。当你打电话给别人时：

1. 建立连接 (Establishment Phase): 网络需要在你和对方之间建立一条连接。这个过程中，沿途的交换机（电话局里的设备）会为这个通话分配并保持一条特定的电路（circuit）。
2. 数据传输 (Data Transfer Phase): 一旦电路建立成功，网络就为这次通话保证了一个恒定的传输速率。你说话的声音信号就能以这个速率稳定地传给对方。
3. 拆除连接 (Teardown Phase): 通话结束后，这个电路会被拆除，之前预留的资源会被释放。

而具体到电路交换网络，书本上这里给出一个例子：4 台电路交换机，它们之间通过 4 条物理链路（比如光纤或电缆）相互连接起来，**每条物理链路**内部被划分成了**4 条独立的电路**。**电路 (Circuit)**: 电路是建立在物理链路之上的**逻辑通道**。通过多路复用技术（见下），一条物理链路的总能力被分割成了多份，每一份就是一个独立的电路。当 Host A 要和 Host B 通信时，网络需要先找到一条从 A 到 B 的路径，这条路径会经过一个或多个交换机和它们之间的物理链路。对于这条路径上的**每一段物理链路**，网络必须从中**选择并预留一条当前空闲的电路**给 A 和 B 的这次通信**专用**。

![由4台交换机和4条链路组成的一个简单电路交换网络](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-13.webp)

### 1. 电路交换网络中的复用

一条物理链路（比如一根光纤或铜线）通常能承载远超单个通话所需的带宽。为了让一条链路能同时支持多条电路（多个通话），电路交换网络使用了多路复用技术。主要有两种方式：

- **频分多路复用 (Frequency-Division Multiplexing, FDM):**就像收音机不同频道占用不同频率一样，FDM 将链路的总频率带宽分割成多个较小的**频段 (frequency band)**，每个建立的电路（连接）**持续占用**其中一个分配给它的频段。电话网络中，每个语音通话通常分配 4kHz 的带宽。
- **时分多路复用 (Time-Division Multiplexing, TDM):** TDM 将时间划分成一个个固定长度的**帧 (frame)**，每个帧再划分成固定数量的**时隙 (time slot)**。当建立一个连接时，网络会在每个帧中为这个连接分配一个固定的时隙。这个连接只能在属于它的那个时隙内传输数据，但在那个时隙内它可以使用链路的全部带宽。

![FDM和TDM](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-14.webp)

关于 TDM，书本上有这样的例子：如果一个 TDM 链路每秒传输 8000 帧，每个时隙包含 8 比特，那么分配到一个时隙的电路，其传输速率就是`8000 帧/秒 * 8 比特/时隙 = 64 kbps`。

从上面这些描述来看，电路交换有很多“缺点”：

- **沉默期间资源闲置**: 在通话中，如果一方暂时不说话（silent periods），为他预留的频段（FDM）或时隙（TDM）就空闲了，但这些资源不能被其他正在进行的通话使用。
- **突发性数据传输效率低**: 比如医生远程看 X 光片，在请求图片和思考图片的间隙，预留的电路资源也是闲置浪费的。
- **建立连接复杂**: 建立端到端的电路需要复杂的信令（signaling）软件来协调沿途所有交换机的操作。

通过一个电路交换网络传输 `640,000` 比特的文件。假设链路使用 TDM，有 `24` 个时隙，链路总速率为 `1.536 Mbps`，建立电路需要 `500` 毫秒 (`0.5`秒)。总共需要多久？

1. 首先计算**每个电路的速率**：`1.536 Mbps / 24 = 64 kbps`；
2. 然后计算**文件传输时间**：`640,000 bits / 64 kbps = 10 秒`；
3. 最后加上`0.5秒`电路建立时间就可以。

> 值得注意的是：这个传输时间 (10 秒) **与路径经过多少个链路无关**。而实际的总延迟还需要考虑[1.4 节](#14-分组交换网中的时延丢包和吞吐量)将会学到的传播时延等等。

### 2. 分组交换和电路交换的对比

与我们之前学的分组交换相比，电路交换更像是为需要稳定、持续、实时性通信（如传统电话）设计的。而分组交换则更灵活、资源利用率更高，更适合互联网上常见的突发性数据传输。

| **基本原理**   | 将报文分割成小的分组，每个分组独立路由传输                            | 建立专用的端到端连接，整个会话期间独占电路       |
| **连接建立**   | 无需建立连接，直接发送分组                                            | 必须先建立专用电路连接（需要500ms等建立时间）    |
| **传输机制**   | 存储转发传输：路由器接收完整分组后再转发                              | 电路建立后直接传输，无需存储转发                 |
| **资源分配**   | 资源共享，按需使用                                                    | 资源预留，连接期间独占（即使沉默期间也占用）     |
| **多路复用**   | 统计多路复用，动态共享链路                                            | FDM（频分）或TDM（时分）多路复用                 |
| **时延特性**   | 存在排队时延，时延不确定                                              | 时延固定且较低（与经过链路数无关）               |
| **端到端时延** | N条链路：$d_{end-end}=N\frac{L}{R}$<br/>P个分组：$(N+P-1)\frac{L}{R}$ | 传输时间与路径链路数无关，仅取决于分配的电路速率 |
| **缓存需求**   | 需要输出缓存/输出队列存储等待分组                                     | 无需缓存，直接传输                               |
| **丢包处理**   | 缓存满时发生分组丢失，需要重传机制                                    | 电路建立后无丢包问题                             |
| **资源利用率** | 高，多用户共享网络资源                                                | 低，沉默期间资源闲置浪费                         |
| **路由选择**   | 使用转发表和路由选择协议动态路由                                      | 电路建立时确定固定路径                           |
| **适用场景**   | 突发性数据传输，如互联网应用                                          | 持续、稳定、实时通信，如传统电话                 |
| **网络复杂度** | 较复杂，需要路由协议和缓存管理                                        | 相对简单，但需要复杂的信令软件                   |
| **典型应用**   | 互联网、局域网、数据传输                                              | 传统电话网络(PSTN)                               |
| **传输保证**   | 不保证带宽和时延，尽力而为                                            | 保证固定带宽和传输速率                           |

#### 关键差异总结

- **分组交换**：灵活高效，适合突发数据，但时延不确定
- **电路交换**：稳定可靠，适合实时通信，但资源利用率低

这两种交换方式各有优势，现代网络往往结合两者特点来满足不同应用需求。

## 1.3.3 网络的网络

所有终端用户（比如我们家里的电脑、手机，或者公司的服务器）都是通过**接入 ISP(Access ISP)**连接到互联网的。但是这些数量庞大（成千上万个）的接入 ISP 之间，是如何互相连接起来，形成一个全球性的互联网的呢？

### 网络结构 0

让每一个接入 ISP 都直接与其他所有接入 ISP 连接起来。但这显然成本太高了，无法实现。想象一下，一个接入 ISP 要拉无数条专线去连接全球成千上万个其他的接入 ISP，这在经济和物理上都是不现实的。

### 网络结构 1: 单一全球 ISP

假设存在一个单一的、覆盖全球的 ISP，我们称之为**全球 ISP(Global ISP)**。所有的接入 ISP 都连接到这个唯一的全球 ISP 上。接入 ISP 是全球 ISP 的**客户(customer)**，全球 ISP 是接入 ISP 的**提供商 (provider)**，接入 ISP 需要向全球 ISP **付费**。这个方法的问题在于对这个全球 ISP 来说，建设和维护这样一个覆盖全球、能接入所有接入 ISP 的网络，成本极其高昂。

### 网络结构 2: 多个竞争的全球 ISP

既然一个全球 ISP 能盈利，自然就会有其他公司也想做这个生意，于是就出现了多个竞争的全球 ISP。

接入 ISP 现在可以根据价格和服务，选择连接到哪个（或哪些）全球 ISP。**但是**这些全球 ISP 之间必须互相连接起来。否则，连接到不同全球 ISP 的接入 ISP 下的用户就无法互相通信了。

### 网络结构 3: 引入区域 ISP 和分层结构

全球 ISP 的概念还是过于理想化，因为没有任何一个 ISP 能真正做到在世界每个角落都有接入点。现实中，网络结构更像一个分层的**体系 (hierarchy)**：

- 区域 ISP (Regional ISP): 在某个地理区域（比如一个省、一个国家的部分地区），可能存在一个或多个区域 ISP。该区域内的接入 ISP 会连接到这些区域 ISP。
- 第一层 ISP (Tier-1 ISP): 这些区域 ISP 又会连接到更上层的 ISP，也就是所谓的 第一层 ISP (Tier-1 ISP)。Tier-1 ISP 就有点像我们之前假设的全球 ISP，它们拥有覆盖范围非常广（但不一定是全球每个角落）的高速骨干网络。世界上大约有十几个 Tier-1 ISP（书中提到了 Level 3, AT&T, Sprint, NTT 等）。它们通常被认为是互联网层级结构的**顶端**。

这些 ISP 的关系：

- 接入 ISP 向它所连接的区域 ISP 付费。
- 区域 ISP 向它所连接的 Tier-1 ISP 付费。
- 接入 ISP 也可以选择**直接连接**到 Tier-1 ISP 并向其付费。
- Tier-1 ISP 之间通常是平等的，它们互相连接，但不需要向上付费

### 网络结构 4: 层级结构 + PoPs + 多宿主 + 对等连接 + IXPs

把下面这些元素（PoP、多宿主、对等连接、IXP）都加入到我们之前的层级模型（网络结构 3）中，就得到了一个更接近现实互联网复杂结构的 网络结构 4。

#### PoP Point of Presence

PoP 是提供商 ISP (provider ISP) 网络中的一个或一组路由器，通常位于某个地理位置，供其客户 ISP (customer ISP) 连接进来。客户 ISP 通常会租用高速线路，将自己的路由器连接到提供商 ISP 位于 PoP 的路由器上。

#### 多宿主 multi-home

指的是一个 ISP（通常是接入 ISP 或区域 ISP）同时连接到两个或更多的提供商 ISP。

- **提高可靠性**： 如果一个提供商 ISP 出现故障，该 ISP 仍然可以通过连接到其他提供商来保持与互联网的连通。
- **优化路由/成本**： 可能根据不同提供商的价格或服务质量来选择性地发送流量。

#### 对等连接 Peering

客户 ISP 需要向提供商 ISP 付费（通常基于流量）。为了减少支付给上游提供商的费用，两个处于同一层级且地理位置相近的 ISP 可能会选择进行对等连接，也即直接用线路将它们的网络连接起来。

#### 互联网交换点 Internet Exchange Points

也叫做 IXP，是一个**物理基础设施**（通常是一个有自己交换机的数据中心或建筑），提供一个中立、高效的场所，让大量 ISP 能够互相直接交换流量，而不需要单独为每个对等伙伴都拉一条专线。

### 网络结构 5: 内容提供商网络 (Content Provider Networks)

像 Google、Facebook、Netflix、Akamai 这样的大型内容提供商，为了更好地服务全球用户，并降低成本、提升服务质量，已经建立了自己的私有全球网络来连接其全球分布的大规模**数据中心**。这个私有网络独立于公共互联网，主要承载该公司自己服务器的流量。

# 1.4 分组交换网中的时延、丢包和吞吐量

**理想 vs. 现实:** 理想是瞬时、无损传输；现实是网络会限制吞吐量、引入时延、并可能丢包。

## 1.4.1 分组交换网中的时延

- 分组在路径上每个节点（主机/路由器）都经历时延 。
- **节点总时延 (Total Nodal Delay)** = 处理时延 + 排队时延 + 传输时延 + 传播时延。

$$d_{nodal} = d_{proc} + d_{queue} + d_{trans} + d_{prop}$$

![路由器A的节点时延](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-16.webp)

### 时延类型

发生在节点，如路由器 A，其出链路前有输出缓存/队列

#### 1. 处理时延 ($d_{proc}$)

- 检查分组首部、决定转发端口、检查比特差错所需时间。
- 量级：高速路由器中通常为微秒 ($\mu s$) 或更低 。

#### 2. 排队时延 ($d_{queue}$)

- 分组在输出队列中等待被传输到链路的时间。
- 取决于队列中已有的分组数量（即网络拥塞程度）。
- 是**可变的** 。
- 量级：微秒 ($\mu s$) 到毫秒 ($ms$) 。

#### 3. 传输时延 ($d_{trans}$)

- 将分组所有比特推向链路所需时间 。
- 计算：$L/R$ （$L$=分组长度，bits；$R$=链路传输速率，bps）。
- 量级：微秒 ($\mu s$) 到毫秒 ($ms$) 。

#### 4. 传播时延 ($d_{prop}$)

- 一个比特从链路起点传播到链路终点所需时间 。
- 计算：$d/s$ （$d$=物理链路长度；$s$=信号传播速度，约 $2 \times 10^8 \sim 3 \times 10^8$ m/s）。
- 量级：广域网中通常为毫秒 ($ms$) 。

#### 5. 传输时延和传播时延的比较

![车队的类比](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-17.webp)

- 传输时延$d_{trans}$与分组长度$L$和链路速率$R$相关，与距离无关。就像收费站把**整个车队**（10 辆车）全部放行到高速公路上所花的时间（比如每放行一辆车 12 秒，10 辆车就是 120 秒 = 2 分钟）
- 传播时延$d_{prop}$与距离$d$相关，与分组长度$L$或链路速率$R$无关。就像**第一辆车**从离开这个收费站行驶到下一个收费站（距离 100 公里，车速 100 公里/小时）所花的时间（1 小时）
- 关键区别：传输是把整个分组“推”出去的时间，传播是单个比特“跑”过去的时间。

也可以通过这个[交互式动画](https://media.pearsoncmg.com/ph/esm/ecs_kurose_compnetwork_8/cw/content/interactiveanimations/transmission-vs-propogation-delay/transmission-propagation-delay-ch1/index.html)来观察区别。

## 1.4.2 排队时延和丢包

- **排队时延 ($d_{queue}$)** 是最复杂、可变的部分。它直接反映了网络的拥塞程度。
- **流量强度 (Traffic Intensity):** $La/R$ （$a$=分组平均到达速率`pkts/sec`）。
  - 若 $La/R > 1$: 平均到达速率超过服务速率，队列将无限增长（理论上），时延趋于无穷。**设计系统必须使 $La/R \le 1$** 。
  - 若 $La/R \le 1$: 时延受流量突发性影响。
  - **规律:** 流量强度 $\to 1$ 时，平均排队时延**急剧**增长
- **丢包 (Packet Loss):**
  - 路由器队列缓存大小是**有限的** 。
  - 当分组到达时队列已满，则该分组会被**丢弃 (drop)** 。
  - 丢包率随流量强度增加而增加 。
  - 丢失的分组可能需要端到端重传 。

![平均排队时延与流量强度的关系](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-18.webp)

## 1.4.3 端到端时延

- 指分组从源主机到目的主机所经历的总时延 。
- 约等于路径上所有节点时延之和。
- **简化模型 (N 段链路, N-1 个路由器, 无拥塞):**
  - $d_{end-to-end} = N \times (d_{proc} + d_{trans} + d_{prop})$ (其中 $d_{trans} = L/R$)
- **Traceroute 工具:**
  - 用于测量到目的主机路径上的路由器以及往返时延 (RTT)。
  - 通过发送特殊分组，并接收沿途路由器的回复消息来实现。
- **其他时延:**
  - 介质访问控制时延 (如 WiFi 争用信道) 。
  - 媒体分组化时延 (如 VoIP 应用填充语音数据包)。

## 1.4.4 计算机网络中的吞吐量

![一个文件从服务器传送到客户的吞吐量](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-19.webp)

- **吞吐量 (Throughput):** 表示数据在端系统之间传输的速率(`bps`)。
- **瞬时吞吐量 (Instantaneous Throughput):** 任意时刻的接收速率。
- **平均吞吐量 (Average Throughput):** 传输总比特数 $F$ / 传输总时间 $T$ = $F/T$。
- **瓶颈链路 (Bottleneck Link):** 端到端路径上，限制了最终吞吐量的链路。
- **简单场景 (单路径, 无干扰流量):**
  - 端到端吞吐量 $\approx$ min{$R_1, R_2, ..., R_N$} (路径上所有链路速率的最小值)。
- **有干扰流量/共享链路:**
  - 吞吐量不仅取决于路径上的链路速率，还取决于这些链路上**共享的其他流量**。
  - 接入网链路 (如 $R_s, R_c$) 常常是瓶颈。
  - 核心网中的共享链路 (速率 R) 也可能成为瓶颈，实际吞吐量取决于该链路如何在其承载的多个数据流之间分配带宽 (如 $R/10$)。

![端到端吞吐量](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/image-20.webp)

## 期末复习：各种时延以及吞吐量计算

#熟悉

### 节点总时延

$$d_{nodal} = d_{proc} + d_{queue} + d_{trans} + d_{prop}$$

### 各类时延计算

| 时延类型                 | 公式                  | 影响因素             | 量级         |
| ------------------------ | --------------------- | -------------------- | ------------ |
| **处理时延** $d_{proc}$  | -                     | 硬件性能             | μs级         |
| **排队时延** $d_{queue}$ | 取决于流量强度 $La/R$ | 网络拥塞程度         | μs~ms        |
| **传输时延** $d_{trans}$ | $L/R$                 | 分组长度L，链路速率R | μs~ms        |
| **传播时延** $d_{prop}$  | $d/s$                 | 物理距离d，传播速度s | ms级(广域网) |

### 端到端时延（无拥塞）

$$d_{end-to-end} = N \times (d_{proc} + d_{trans} + d_{prop})$$

### 关键概念

### 流量强度与排队时延

- **流量强度**: $\rho = La/R$ （L=分组长度，a=到达速率，R=链路速率）
- **设计原则**: 必须保证 $La/R \leq 1$
- **性能特点**: 当 $\rho \to 1$ 时，排队时延急剧增长

### 吞吐量计算

- **平均吞吐量**: $\text{Throughput} = F/T$ （F=总比特数，T=传输时间）
- **瓶颈原理**: 端到端吞吐量 = $\min\{R_1, R_2, ..., R_N\}$
- **共享链路**: 实际吞吐量还需考虑其他流量的影响

### 计算公式

#### 1. 传输vs传播时延对比

- **传输时延**: 把整个分组"推出去"的时间 = $L/R$
- **传播时延**: 单个比特"跑过去"的时间 = $d/s$

#### 2. 存储转发时延

- **单个分组经过N条链路**: $d = N \times L/R$
- **P个分组经过N条链路**: $d = (N+P-1) \times L/R$

#### 3. 丢包分析

- 当队列满且新分组到达时发生丢包
- 丢包率随流量强度增加而上升
- 需要端到端重传机制处理

### 重要参数值

- **光速**: $s \approx 2 \times 10^8 \sim 3 \times 10^8$ m/s
- **处理时延**: 通常μs级或更低
- **关键阈值**: 流量强度接近1时性能急剧恶化

- 排队时延：是主要的可变时延，它取决于路由器当时的拥塞程度，即有多少其他分组也在排队等待。

# 1.5 协议层次与服务模型

- **目的:** 为了管理复杂网络系统的设计，将其组织成**层次 (layers)** 结构。

## 1.5.1 层次体系结构

- **复杂系统管理:** 现实中我们常用分层方法理解复杂系统。
- **类比：航空旅行系统**
  - 功能分层：票务 -> 行李 -> 登机口 -> 起飞/降落 -> 航线路由。
  - 每层提供服务：通过执行本层动作，并使用**下层**提供的服务。
  - 优点：
    - **模块化 (Modularity):** 便于讨论、理解系统的特定部分。
    - **易于更新:** 更改某一层实现方式时，只要该层对上层提供的服务和对下层要求的服务不变，就不会影响系统其他部分。
- **网络协议分层 (Protocol Layering)**
  - 网络软硬件也按层组织，形成**协议栈 (protocol stack)**。
  - 每层协议实现一种**服务模型 (service model)**，向上层提供服务。
  - 实现方式：执行本层功能 + 调用下层服务。
  - 实现位置：可在软件、硬件或两者结合中实现 (应用/传输层多为软件；物理/链路层多在硬件网卡；网络层常为混合)。
  - **优点:** 结构清晰、模块化、易于维护更新。
  - **潜在缺点:** 可能有功能冗余；某层功能可能需要其他层的信息，破坏层次分离。
- **因特网协议栈 (Internet Protocol Stack) - 5 层模型**
  - **应用层 (Application Layer):**
    - 网络应用程序及其协议 (HTTP, SMTP, FTP, DNS)。
    - 在端系统间交换**报文 (message)**。
  - **运输层 (Transport Layer):**
    - 负责端点应用程序进程间的报文传输。
    - 协议：TCP (面向连接、可靠传输、流量控制、拥塞控制) 和 UDP (无连接、不可靠、“无额外服务”)。
    - 交换**报文段 (segment)**。
  - **网络层 (Network Layer):**
    - 负责将**数据报 (datagram)** 从一台主机路由到另一台主机。
    - 核心协议：IP 协议 (定义数据报格式、编址、主机和路由器行为)。
    - 包含路由选择协议 (决定路径)。
    - 常被称为“IP 层”。
  - **链路层 (Link Layer):**
    - 负责将数据报通过**单个链路**从一个节点（主机或路由器）移动到下一个节点。
    - 提供的服务依赖具体协议 (如 Ethernet, WiFi, PPP)，可能包含可靠传输。
    - 沿路径的不同链路可能使用不同协议。
    - 交换**帧 (frame)**。
  - **物理层 (Physical Layer):**
    - 负责在链路上移动帧中的**每一个比特 (bit)**。
    - 协议与物理传输介质 (双绞线、光纤、无线电) 相关。

> 我的思考：主机 A 的网络层是和主机 A 的运输层以及链路层相连，还是和主机 B 的网络层相连？
> 解答：主机 A 的网络层既和主机 A 的运输层、链路层直接相连（物理交互），也和主机 B 的网络层逻辑相连（通过协议进行对等通信）。换句话说，正是因为分层的设计，网络层不需要关心运输层或者链路层会怎样操纵数据，A 的网络层发送的数据最终传递到主机 B 后对于 B 的网络层是可以用相同的协议直接理解数据的。

## 1.5.2 封装

- **数据流动:** 数据在发送端**自顶向下**通过协议栈，在接收端**自底向上**通过协议栈。中间的交换机/路由器只处理较低层。
  - 链路层交换机处理第 1、2 层。
  - 路由器处理第 1、2、3 层。
  - 主机处理所有 5 层。
- **封装过程:**
  - 在发送端，每层协议会给**上层传下来的数据单元 (payload)** 添加本层的**首部信息 (header)** (有时还有尾部)。
  - 应用层: 报文 M
  - 运输层: M + 运输层首部 Ht -> 报文段 (Segment)
  - 网络层: Segment + 网络层首部 Hn -> 数据报 (Datagram)
  - 链路层: Datagram + 链路层首部 Hl -> 帧 (Frame)
- **类比:** 办公室备忘录 (报文) -> 内部信封 (报文段) -> 邮政信封 (数据报)。
- **解封装 (De-encapsulation):** 在接收端进行相反的过程，逐层去掉首部，将数据交给上层。
- **注意:** 大报文可能被分片 (fragmentation) 成多个分组，在接收端需要重组 (reassembly)。

### 模型结构对比

| OSI 七层模型               | TCP/IP 四层模型                 | 主要功能                     | 典型协议/技术                       |
| -------------------------- | ------------------------------- | ---------------------------- | ----------------------------------- |
| **应用层** (Application)   | **应用层** (Application)        | 为用户应用程序提供网络服务   | HTTP, HTTPS, FTP, SMTP, DNS, Telnet |
| **表示层** (Presentation)  | ↗️ 合并到应用层                 | 数据格式转换、加密解密、压缩 | SSL/TLS, JPEG, MPEG, ASCII          |
| **会话层** (Session)       | ↗️ 合并到应用层                 | 建立、管理、终止会话连接     | NetBIOS, RPC, SQL sessions          |
| **传输层** (Transport)     | **传输层** (Transport)          | 端到端可靠数据传输           | **TCP, UDP**                        |

| **数据链路层** (Data Link) | **网络接口层** (Network Access) | 帧封装、错误检测、MAC地址    | Ethernet, WiFi, PPP                 |
| **物理层** (Physical)      | ↗️ 合并到网络接口层             | 比特流的物理传输             | 电缆、光纤、无线信号                |

### 详细层次分析

#### OSI 模型 (理论标准)

##### 上三层 - 面向应用

- **应用层**: 直接为用户程序提供服务
- **表示层**: 处理数据的语法和语义（加密、压缩、格式转换）
- **会话层**: 管理应用程序间的对话

##### 下四层 - 面向通信

- **传输层**: 提供端到端的数据传输服务
- **网络层**: 处理数据包的路由和转发
- **数据链路层**: 在直连节点间可靠传输帧
- **物理层**: 传输原始比特流

#### TCP/IP 模型 (实际实现)

##### 应用层

- **功能**: 整合了OSI的应用层、表示层、会话层功能
- **特点**: 更加实用，直接面向具体应用需求

##### 传输层

- **TCP**: 面向连接，可靠传输，流量控制，拥塞控制
- **UDP**: 无连接，不可靠但高效，适合实时应用

##### 网络层 (Internet层)

- **IP协议**: 核心协议，提供无连接的数据包传输
- **路由功能**: 在复杂网络中找到最佳路径

##### 网络接口层

- **功能**: 整合了OSI的数据链路层和物理层
- **特点**: 与具体的网络硬件技术相关

### 主要区别总结

#### 1. 层次数量

- **OSI**: 7层（理论完整）
- **TCP/IP**: 4层（实用简化）

#### 2. 设计理念

- **OSI**: 先有理论模型，后有协议实现
- **TCP/IP**: 先有协议实现，后总结出模型

#### 3. 实际应用

- **OSI**: 主要用作教学和理论参考
- **TCP/IP**: 互联网的实际标准

#### 4. 协议绑定

- **OSI**: 模型与协议相对独立
- **TCP/IP**: 模型与具体协议紧密结合

#### 5. 灵活性

- **OSI**: 层次分工明确，但可能过于复杂
- **TCP/IP**: 层次合并，更加灵活实用

### R22

列出一个层次能够执行的 5 个任务。这些任务中的一个（或两个）可能由两个（或更多）层次执行吗？

#### A22

一个层次能够执行的任务示例：

1.  **差错控制:** 检测或纠正传输中产生的比特差错。
2.  **流量控制:** 协调发送方和接收方的速率，避免淹没接收方。
3.  **分段与重组:** 将大块数据拆分成小的数据包，并在接收端重新组装。
4.  **多路复用/分用:** 允许多个上层会话共享一个下层连接，并在接收端分发给正确的上层会话。
5.  **寻址/路由:** 确定数据传输的路径或下一跳，并在首部包含必要的地址信息。
6.  **(额外) 连接建立:** 在数据传输前建立连接状态。
7.  **(额外) 可靠数据传输:** 确保数据无差错、按顺序到达，通常通过确认和重传来完成。

是的，某些任务可能由多个层次执行。例如，**可靠数据传输**（包含差错控制和恢复）可能在链路层（逐跳可靠性）和运输层（端到端可靠性，如 TCP）都提供。这有时被视为分层的缺点之一（功能冗余）。

### R23

因特网协议栈中的 5 个层次有哪些？在这些层次中，每层的主要任务是什么？

#### A23

因特网协议栈的 5 个层次及其主要任务是：

1.  **应用层 (Application Layer):** 支持网络应用程序（如 HTTP, SMTP, DNS），是用户与网络的接口。
2.  **运输层 (Transport Layer):** 在应用程序进程之间提供端到端的数据传输服务（如 TCP, UDP）。

### R24

什么是应用层报文？什么是运输层报文段？什么是网络层数据报？什么是链路层帧？

#### A24

- **应用层报文 (Message):** 由网络应用程序产生的数据单元，是应用程序要交换的信息。
- **运输层报文段 (Segment):** 由运输层创建，通常包含一个应用层报文和运输层添加的首部信息（如 TCP 或 UDP 首部）。
- **网络层数据报 (Datagram):** 由网络层创建，通常包含一个运输层报文段和网络层添加的首部信息（如 IP 首部）。
- **链路层帧 (Frame):** 由链路层创建，通常包含一个网络层数据报和链路层添加的首部信息（及可能的尾部信息，如以太网帧）。

### R25

路由器处理因特网协议栈中的哪些层次？链路层交换机处理的是哪些层次？主机处理的是哪些层次？

# 1.6 面对攻击的网络 (Networks Under Attack)

- **背景:** 互联网至关重要，但也面临严重安全威胁。网络安全旨在理解攻击并进行防御。
- **恶意软件 (Malware):**
  - 通过互联网感染主机（电脑、手机、物联网设备等）。
  - 危害：删除文件、安装间谍软件（窃取密码、个人信息）、将主机变成**僵尸网络 (botnet)** 的一部分被远程控制。
  - **自我复制型恶意软件 (Self-replicating malware):** 能自动从一台受感染主机传播到另一台，扩散迅速。
- **拒绝服务攻击 (Denial-of-Service, DoS):**
  - 目标：使网络、主机或服务对合法用户不可用。
  - 主要类型：
    - **漏洞攻击 (Vulnerability attack):** 发送特殊构造的报文利用目标应用或系统的缺陷，使其崩溃或停止服务。
    - **带宽洪泛 (Bandwidth flooding):** 向目标发送海量数据包，堵塞其接入链路。
    - **连接洪泛 (Connection flooding):** 建立大量 TCP 连接（半开或全开），耗尽目标主机的连接资源。
  - **分布式拒绝服务 (Distributed DoS, DDoS):**
    - 攻击者控制**多个**（通常是**僵尸网络**中的）受害主机，同时向目标发起 DoS 攻击。
    - 总流量巨大，更难防御。
- **分组嗅探 (Packet Sniffing):**
  - 被动地监听并记录网络上传输的数据包副本。
  - 在**无线网络**中尤其容易实现，但也可能发生在有线网络（如广播型 LAN、被入侵的路由器）。
  - 可获取密码、隐私信息等敏感内容。
  - 因为被动，难以检测。主要防御手段是**加密**。
- **伪装/IP 欺骗 (Masquerading / IP Spoofing):**
  - 发送源地址为**伪造**地址的数据包。
  - 可用于隐藏攻击者身份、绕过基于地址的认证、或执行其他欺骗行为。
  - 表明需要**端点认证 (end-point authentication)** 机制来验证通信方的真实身份。
- **历史原因:** 互联网早期设计基于“互相信任的用户连接到一个透明网络”的模型，默认缺乏安全机制。现代互联网环境复杂，信任缺失，安全挑战严峻。

| **连接洪泛** | 建立大量TCP连接    | 耗尽目标主机连接资源   |

利用僵尸网络中的多个主机同时攻击就升级为：DDoS

### 伪装攻击 (IP Spoofing)

通过发送**源地址为伪造地址**的数据包来攻击

- **隐藏身份**：掩盖真实攻击源（恶意身份可以冒充客户/服务器）
- **绕过认证**：欺骗基于IP地址的访问控制
- **身份冒充**：伪装成可信主机

可以需要**端点认证机制**来验证通信方的真实身份，具体来说：

- HTTPS通过数字证书，CA签名来防止恶意冒充服务器
- 第三方OAuth登陆防止恶意冒充用户

## 复习题

### R26

病毒和蠕虫之间有什么不同？

#### A26

- **病毒 (Virus):** 通常需要**依附**于一个宿主文件或程序。它的传播通常需要用户的某种行为（如运行被感染的程序、打开带毒的附件）。病毒会感染其他文件。
- **蠕虫 (Worm):** 是一种**独立**的恶意软件，不需要宿主文件。它能**主动地**在网络中自我复制和传播，通常利用操作系统或应用程序的漏洞，**无需用户干预**即可感染其他计算机。
- (书中主要使用更广泛的术语“**自我复制型恶意软件 (self-replicating malware)**” 来涵盖这类能自动传播的威胁。)

### R27

描述如何产生一个僵尸网络，以及僵尸网络是怎样被用于 DDoS 攻击的。

#### A27

- **产生僵尸网络 (Botnet Creation):**
  1.  攻击者通过各种手段（如蠕虫、病毒、木马、钓鱼邮件等）将恶意软件植入大量用户的计算机（或其他联网设备）中。
  2.  这些恶意软件使受感染的主机（称为“**僵尸机/bots/zombies**”）能够被攻击者（称为“**僵尸网络主控者/botmaster**”）远程控制。
  3.  由这些被控主机组成的网络就是**僵尸网络**。
- **用于 DDoS 攻击:**
  1.  僵尸网络主控者向其控制的所有（或部分）僵尸机发出指令。
  2.  所有收到指令的僵尸机**同时**向同一个目标（如某个网站的服务器）发送大量的无效请求或数据流（进行带宽洪泛或连接洪泛）。
  3.  来自成百上千台僵尸机的**聚合流量**会远远超过目标服务器或其网络链路的处理能力，导致合法用户无法访问服务，从而实现**分布式拒绝服务 (DDoS)**。

### R28

假定 Alice 和 Bob 经计算机网络互相发送分组。假定 Trudy 将自己安置在网络中，使得她能够俘获由 Alice 发送的所有分组，并发送她希望给 Bob 的东西；她也能够俘获由 Bob 发送的所有分组，并发送她希望给 Alice 的东西。列出在这种情况下 Trudy 能够做的某些恶意的事情。

#### A28

Trudy 处于“**中间人 (Man-in-the-Middle)**”的位置，她可以进行多种恶意活动：

1.  **窃听 (Eavesdropping/Sniffing):** Trudy 可以阅读 Alice 和 Bob 之间传输的所有分组的内容，获取敏感信息（如密码、银行账号、私人对话），侵犯**机密性**。
2.  **篡改 (Modification/Tampering):** Trudy 可以拦截分组，修改其内容（如更改转账金额或收款人），然后再发送给接收方，破坏数据的**完整性**。
3.  **伪装/冒充 (Impersonation/Masquerading):** Trudy 可以伪造来源，冒充 Alice 向 Bob 发送消息，或者冒充 Bob 向 Alice 发送消息，破坏通信的**认证性**。
4.  **拒绝服务 (Denial of Service):** Trudy 可以直接丢弃所有（或部分）在 Alice 和 Bob 之间传输的分组，阻止他们通信，破坏**可用性**。
5.  **重放攻击 (Replay Attack):** Trudy 可以记录下 Alice 或 Bob 发送的合法分组，然后在稍后的时间重新发送这些分组，可能导致重复操作（如重复转账）。
