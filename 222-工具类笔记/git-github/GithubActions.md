# Github Actions

本质上是 yaml 语法的一个配置文件，一个自动化助手，住在你的 GitHub 仓库里。这个助手能帮你做很多事情，比如每次你提交代码时自动运行测试，或者在你发布新版本时自动部署网站 。

1.  **Workflow (工作流):** 这就像是给助手的一份详细**计划书**或**蓝图** [2, 3]。你用一种叫做 YAML 的格式写这份计划书，并把它放在仓库里一个特殊的地方：`.github/workflows/` 目录下 [2]。这份计划书规定了什么时候（由事件触发）要做什么（包含一个或多个作业）[2, 3]。
2.  **Event (事件):** 这就是**触发**计划书执行的**信号** [2, 3]。比如，“有人推送了代码”（`push` 事件），“有人创建了拉取请求”（`pull_request` 事件），或者到了“预定时间”（`schedule` 事件），甚至是你“手动按下按钮”（`workflow_dispatch` 事件）[2, 4]。
3.  **Job (作业):** 计划书里的一个**主要任务** [2, 3]。比如，“构建应用程序”是一个作业，“运行测试”是另一个作业。默认情况下，不同的作业可以同时进行（并行），但你也可以设定顺序，比如必须先构建成功才能测试 [2, 3]。每个作业都在一个叫做“运行器”的机器上完成 [2]。
4.  **Step (步骤):** 一个作业里的具体**操作指令** [2, 3]。比如，“下载代码”、“安装某个软件”、“运行一个命令”都是步骤。一个作业里的所有步骤是按顺序执行的，并且在同一个运行器上完成，所以它们可以共享文件 [2]。
5.  **Action (动作):** 这是别人预先写好的、可重用的**工具或小程序** [2, 5]。比如，有一个专门用来下载代码的动作 (`actions/checkout`)，还有一个专门用来设置 Node.js 环境的动作 (`actions/setup-node`)。使用这些动作可以让你少写很多重复的指令 [2, 6]。你可以在 GitHub Marketplace 找到很多这样的动作 [2]。
6.  **Runner (运行器):** 这就是实际**执行**作业和步骤的**计算机**（通常是虚拟机）[2]。GitHub 提供了多种类型的运行器（Linux, Windows, macOS），它们每次运行都是一个干净的环境 [2, 7]。你也可以用自己的计算机作为运行器（自托管运行器）[2, 8]。

## Examples

### 最基本的

```yaml
name: Hello World Workflow

on:
  workflow_dispatch:

jobs:
  say-hello:
    runs-on: ubuntu-latest

    steps:
      - name: Say Hello
        run: echo "Hello, Gtihub Actions!"

      - name: Show date
        run: date
```
