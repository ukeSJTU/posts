# Cheatsheet 3: 贪心算法 (Greedy Algorithms)

## 1. 贪心策略基本思想 (General Idea)

- **核心**: 在每一步选择中都采取当前状态下最好或最优（即最有利）的选择，从而希望导致结果是全局最好或最优的。贪心算法不从整体最优上加以考虑，它所作出的选择只是在某种意义上的**局部最优选择**。
- **特点**:
  - 通常简单、高效。
  - 不一定能得到全局最优解。
  - 关键在于证明所选的贪心策略确实能导出全局最优解 (如果可以的话)。

## 2. 贪心算法证明框架 (Proof Framework)

证明贪心算法得到最优解的常用方法：

- **贪心选择性质 (Greedy Choice Property)**: 证明所做的局部最优选择，可以包含在某个全局最优解中。即证明一个全局最优解可以通过局部最优选择来达到，或者可以通过修改转化为包含该局部最优选择而不影响其最优性。
  - **常用技巧**:
    - **交换论证 (Exchange Argument)**: 假设存在一个最优解不包含当前的贪心选择，通过交换元素的方式，构造出另一个包含贪心选择且结果不差于 (甚至优于) 原最优解的新解。 (例如 Huffman 编码证明, 活动选择证明)。
    - **“保持领先” (Staying Ahead)**: 证明贪心算法的每一步选择都“不劣于”任何其他算法在同一步的选择，最终得到最优解。
    - **结构性证明**: 证明问题具有某种结构 (如 Matroid)，使得贪心策略必然产生最优解。
- **最优子结构 (Optimal Substructure)**: 证明问题的最优解包含了其子问题的最优解。这是应用贪心和动态规划的基础。

## 3. 具体算法示例 (Examples)

### 3.1 作业调度 (Homework Scheduling / Interval Scheduling with Deadlines)

- **问题**: 给定 n 个作业，每个作业 $j$ 有处理时间 $s_j$ 和截止时间 $d_j$。目标是找到一个完成作业的顺序，使得超期时间 (Lateness) 最小化 (或检查是否存在一个不超期的调度)。
- **贪心策略 (Earliest Deadline First - EDF)**: 优先处理**截止时间最早**的作业。
- **正确性**: (对于检查是否能按时完成所有作业) 如果 EDF 策略无法按时完成所有作业，那么没有其他任何调度可以按时完成。
  - **证明思路**: 假设 EDF 在第 $i$ 个作业首次超期，即 $\sum_{k=1}^i s_k > d_i$。由于 EDF 策略，这 $i$ 个作业的截止时间 $d_k \le d_i$。任何其他调度要完成这 $i$ 个作业，也至少需要 $\sum_{k=1}^i s_k$ 的时间，因此在 $d_i$ 之前也无法完成这 $i$ 个作业中的某一个 (特别是第 $i$ 个，如果按 EDF 顺序)。
- **复杂度**: 按截止时间排序需要 $O(n \log n)$。

### 3.2 活动选择 (Activity Selection)

- **问题**: 给定 n 个活动，每个活动 $i$ 有开始时间 $start_i$ 和结束时间 $finish_i$。选择尽可能多的**互相兼容** (时间不重叠) 的活动。
- **贪心策略 (Earliest Finish Time - EFT)**: 每次从未选择的活动中，选择**结束时间最早**且与已选活动兼容的活动。
- **其他贪心策略 (可能错误)**:
  - 最早开始时间 (Start Time First)
  - 最短持续时间 (Shortest Length First)
- **正确性 (EFT)**:
  - **贪心选择**: 选择结束时间最早的活动 $a_1$。假设存在最优解 $OPT$ 不包含 $a_1$，设 $OPT$ 中第一个活动是 $a_k$。由于 $a_1$ 结束时间最早，$finish(a_1) \le finish(a_k)$。用 $a_1$ 替换 $a_k$ 得到的解 $OPT' = \{a_1\} \cup (OPT - \{a_k\})$ 仍然是兼容的，且活动数量不少于 $OPT$。因此，总存在一个最优解以贪心选择 $a_1$ 开始。
  - **最优子结构**: 选择活动 $a_1$ 后，问题转化为在与 $a_1$ 兼容的剩余活动中选择尽可能多的活动，这是一个规模更小的同类子问题。
- **复杂度**: 按结束时间排序 $O(n \log n)$，然后线性扫描 $O(n)$。总复杂度 $O(n \log n)$。

### 3.3 最小生成树 (Minimum Spanning Tree - MST)

- **问题**: 见 Cheatsheet 2。
- **Prim 算法**: 贪心策略是每次选择连接已选顶点集 $S$ 和未选顶点集 $V-S$ 的**权重最小**的边。其正确性基于 Cut Property。
- **Kruskal 算法**: 贪心策略是按边权从小到大考虑，只要不形成环就加入该边。其正确性基于 Cycle Property。
- **复杂度**: 见 Cheatsheet 2。

### 3.4 Huffman 编码 (Huffman Coding)

- **问题**: 给定字符集及其出现频率，找到一种最优的**前缀无关 (prefix-free)** 二元编码方案，使得编码后的总长度 (按频率加权) 最小。
- **前缀无关码**: 任何字符的编码不是另一个字符编码的前缀。可以用二叉树表示，字符仅出现在叶节点。编码长度等于叶节点深度。
- **代价 (Cost)**: $\sum_{a \in A} depth(a) \cdot freq(a)$。
- **贪心策略 (Huffman 算法)**:
  1.  将每个字符视为一个叶节点，权重为其频率。
  2.  重复以下步骤直到只剩一个节点：
      - 选择当前权重最小的两个节点 (或子树根节点) $x, y$。
      - 创建一个新的父节点 $z$，其权重为 $weight(x) + weight(y)$，并将 $x, y$ 作为其子节点。
      - 用 $z$ 替换 $x, y$。
- **正确性**:
  - **引理**: 最优编码树中，频率最低的两个字符一定是兄弟节点，且处于树的最深层。(可用交换论证证明)
  - **贪心选择**: 合并频率最低的两个节点 $x, y$ 为子树 $z$。将 $z$ 视为一个频率为 $freq(x)+freq(y)$ 的新字符，原问题归约为对 $n-1$ 个字符（包含新字符 $z$）求最优编码。
  - **最优子结构**: 原问题的最优编码树可以通过子问题（$n-1$ 个字符）的最优编码树加上将 $z$ 替换回 $x, y$ 子节点得到。
- **时间复杂度**:
  - 使用最小堆 (Min-Heap) 维护节点权重：初始化 $O(n)$，每次提取最小和插入需要 $O(\log n)$，共 $n-1$ 次合并。总复杂度 $O(n \log n)$。
  - 如果频率已排序: 可以使用两个队列（一个存初始节点，一个存合并后的节点），每次从两个队头取最小的两个，合并后放入第二个队列。总复杂度 $O(n)$。
- **最优性讨论**: Huffman 编码在**二元、基于字符、前缀无关**的编码中是最优的。但在某些情况下 (如字符频率非常接近 $1/3, 1/3, 1/3$)，三元编码可能更优。当字符频率都是 $2$ 的负幂次时，Huffman 编码长度等于信息熵下界。

### 3.5 最小化最大完工时间 (Makespan Minimization)

- **问题**: 给定 $m$ 台相同的机器和 $n$ 个作业，每个作业 $j$ 有处理时间 $p_j$。将作业分配给机器，使得所有机器中**最后完成作业的时间 (Makespan)** 最小化。该问题是 NP-hard。
- **算法 1: 列表调度 (List Scheduling / Simple Greedy)**:
  - **策略**: 按任意顺序处理作业，将每个作业分配给当前**最早完成**的机器。
  - **性能**: 2-近似算法 (Approximation Algorithm)，即 $ALG \le 2 \cdot OPT$。
  - **证明思路**: 考虑最后完成的作业 $p_n$。设其完成时间为 $T = ALG$。在 $p_n$ 开始执行的时刻 $t$，所有机器都处于忙碌状态 (否则 $p_n$ 会被分到更早结束的机器上)。因此，总工作量 $\sum p_i \ge m \cdot t$。而最优解 $OPT \ge (\sum p_i) / m \ge t$，同时显然 $OPT \ge p_n$。所以 $ALG = t + p_n \le OPT + OPT = 2 \cdot OPT$。这个界是紧的。
- **算法 2: LPT (Longest Processing Time First)**:
  - **策略**: 先将作业按处理时间**降序**排列，然后按此顺序进行列表调度。
  - **性能**: (4/3)-近似算法，即 $ALG_{LPT} \le \frac{4}{3} \cdot OPT$。
  - **证明思路 (简化版，得到 $3/2$-近似)**: 同样考虑最后完成的 (最短的) 作业 $p_n$。$ALG = t + p_n$。由于是 LPT，所有其他作业 $p_i \ge p_n$。如果 $n > m$，则前 $m+1$ 个作业的处理时间都 $\ge p_n$。最优解中，至少有一台机器要处理这 $m+1$ 个作业中的至少两个，因此 $OPT \ge 2p_n$。结合 $ALG = t + p_n \le OPT + p_n$，得到 $ALG \le OPT + OPT/2 = \frac{3}{2} OPT$。
  - **证明思路 (4/3-近似)**: 需要更细致的分析，特别是当 $OPT < 3p_n$ 时，可以证明 LPT 得到的是最优解 ($ALG=OPT$)。结合 $OPT \ge 3p_n$ 时 $ALG = t+p_n \le OPT + p_n \le OPT + OPT/3 = (4/3) OPT$。
  - 这个界也是紧的。
- **更好算法**: 存在 PTAS (Polynomial Time Approximation Scheme) 和 EPTAS，可以在多项式时间 (依赖于 $1/\epsilon$) 内达到 $ALG \le (1+\epsilon)OPT$ 的性能保证。
