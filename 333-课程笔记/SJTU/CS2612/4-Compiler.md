# 简单编译器

一个简易的编译器，其核心任务是将我们编写的高级语言（例如C、Java）代码，一步步地转化为计算机硬件能够直接执行的低级汇编代码。这个过程主要包含以下几个关键阶段：

- **拆分复合表达式：** 汇编语言的指令通常非常基础，每次只能执行一个简单的操作（如加法、乘法或数据移动）。因此，像 x = a*b + c*d; 这样的复杂语句必须被拆分成一系列单一运算的指令。
- **生成基本块 (Control Flow Graph)：** 高级语言中的 if-else 或 while 等控制结构，在汇编层面是通过有条件的跳转指令实现的。为了系统地处理这些跳转，我们会将代码分割成多个“基本块”，并将它们组织成一个“控制流图”（Control Flow Graph, CFG），清晰地展示了程序的执行路径。
- **寄存器分配：** CPU 中用于存储临时数据的地方是寄存器，其数量非常有限但速度极快。为了提升程序运行效率，我们需要尽可能地将程序中的变量（包括拆分表达式时产生的临时变量）存放在寄存器中。
- **生成汇编代码：** 在完成上述所有准备工作后，最后一步就是将这些中间表示（IR）和寄存器分配方案，翻译成最终的、特定于目标硬件平台的汇编指令。

上述流程是一个为了教学而简化的模型。在真实的现代编译器如 GCC 或 LLVM 中，最大且最复杂的部分是**编译优化**。编译器会花费大量的精力去分析和转换代码，使其运行得更快、占用内存更少，而这通常涉及到成百上千种不同的优化技术。

## 拆分复合表达式

在高级语言中，我们可以在一条语句里完成多个计算，但这在汇编语言中是无法直接实现的。因此，首要任务就是将这些复杂的表达式“扁平化”，确保每个赋值语句最多只执行一步运算。

拆分前：`x = y*y + z*z`

拆分后：

```
#0 = y * y  // 临时变量 #0 存储 y*y 的结果
#1 = z * z  // 临时变量 #1 存储 z*z 的结果
x = #0 + #1 // 将两个中间结果相加并赋给 x
```

**关键点回顾与补充：**

1. **每个赋值语句至多进行一步计算：** 这条规则也包括从内存中加载数据。例如，x = _(address) + 1 可能会被拆分为 #0 = _(address) 和 x = #0 + 1 两步。这个过程通常通过递归遍历表达式的抽象语法树（AST）来完成。
2. **转化后的程序仅在必要处保留树结构：** 经过拆分，原本嵌套的表达式树结构被拉平为线性的指令序列。只有像 if-else 和 while 这样的控制流结构，才需要保留其分支或循环的结构。
