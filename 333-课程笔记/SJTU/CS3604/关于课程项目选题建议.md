结合我对本专业培养计划的了解，绝大多数按部就班上课的同学，其核心编程能力主要集中在 Python 和 C++，掌握数据结构与算法基础，但对于 Web 开发（前端/后端/数据库）几乎是零经验。同时，对于 Git 和 GitHub，大家多停留在基础命令的使用，缺乏多人协作及冲突解决的实战经验。

在这一背景下，课程要求复刻 12306 或携程这样复杂的 Web 项目，存在一定的挑战：

1. 简单的 HTML/CSS 已无法满足现代 Web 开发需求，同学被迫在短时间内学习 React/Vue 及异步编程，学习曲线过于陡峭。
2. 虽然课程鼓励使用 AI，但由于缺乏基础知识，同学们往往难以判断 AI 生成代码的逻辑，调试困难，导致最终项目可能变成了“被 AI 带着走”，偏离了锻炼工程能力的初衷。这一点在课程后期组间协作更加突出。
3. 商业网站（如 12306）的后台逻辑（如订单流转、退改签规则）是黑盒的，我们在开发时难以确定标准需求，容易陷入猜测或随意实现的境地。

基于上述分析，关于未来的课程项目设计，我有两个不同方向的建议供您参考：

方案一：保留 Web 开发，但是利用前后端分离特性来降低一些负担：

如果考虑到课程需配合实验室 **WebTestPilot** 工具的使用，必须保留 Web 项目，那么我比较建议更换一个业务逻辑更清晰、更适合教学的目标网站，或者由助教直接提供靶点网站。

目前模仿 12306/携程这类外部商业网站存在一个工程上的痛点：这些网站的后台逻辑是不可观测的黑盒。例如，我们无法确切知道成功预定机票后或退款后的订单详情页逻辑，网站本身也可能会更新。这导致开发时大家往往只能凭空假设需求，或者让 AI 自由决定，这不利于每一组的需求管理。

建议转向模仿一个业务更专一的平台（例如博客平台 Medium）。“简单”并不代表缺乏深度，这样的项目依然涵盖了 Web 开发的所有核心方向：前端布局、页面路由、后端 API 设计、登录与鉴权、数据库设计等。

在此方向上，我强烈推荐参考开源项目 `gothinkster/realworld`，链接是：https://github.com/gothinkster/realworld 。

- 该项目旨在设计一个模仿 Medium 的文章平台。它提供了完整的 API Specs（接口规范）以及每个页面的基础 HTML/CSS（基于 Bootstrap）。
- 项目本身不提供代码实现，而是提供标准。这意味着助教可以直接分发前端模板和接口文档，让同学们专注于后端实现（可以使用大家熟悉的 Python FastAPI）。
- 如果课程的重点在于管理需求，那我觉得这个项目也可以作为前期的一个小项目，这能让同学们在有明确参考的前提下，理解如何将“需求文档”转化为“Web 项目”，而不是在前端样式和猜测需求中耗费精力。同时为大作业如何整理需求有更加明确的参考。

---

方案二：Python TUI 项目开发

考虑到同学们的 Python 基础，我建议尝试利用 TUI 库（如 `Textual`: [https://textual.textualize.io/](https://textual.textualize.io/)）开发命令行工具，例如一个类似 Lazygit 的 Git Client。

我觉得 Python 语言对大家更友好，相对来说 AI 写错了比较容易发现或者自行 debug。

Python 并不是不可以开发 Web 项目，例如可以 Django 当作后端 + 自带的 Template 来渲染前端页面，但是这个框架可能对于我们的课程而言太重了。还有一些比较新的解决方案例如 NiceGUI，但是这种轻型框架难以处理需要复杂交互的前端。

TUI 保留了“所见即所得”的视觉反馈，开发起来成就感更强，也比较好肉眼验证程序运行是否正确。而且借助 Textual 这个比较成熟的框架其实可以做相当复杂的一个软件。
