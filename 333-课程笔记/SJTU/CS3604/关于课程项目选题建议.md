首先，我很喜欢本学期这门课程，我在这个课上学到了很多有意思的开发技巧，老师和助教也都非常负责有帮助。

但是我想说这么课程的选题是有问题的，我对于这门课的喜爱与我看到选课社区上对这么课程的低分评价让我感到非常难过，我想给林老师作为学生来提一些建议。我也不是对分数有什么追求，而是只是纯粹的希望这门课程的内容更完善

林老师可能不了解我们这个专业的普通学生（这里普通我想指的是正常跟随专业培养计划上课做作业，没有进行过课外拓展的）学生应该只会两种语言：python 和 C++。掌握了数据结构和基本的代码编写能力，但是没有前端/后端/数据库等等开发经验。对于绝大部分学生来说 sql 都是陌生语言。同时 Git 和 Github 基本上也都是能用但不精通，即不理解 Git 的底层原理，也少有 Github 上开源项目合作的经验

先说这个学期我们干了什么：

前几周上课

再简略分析一下林老师上课提到的斯坦福大学新开设的类似的一门课程CS146S。我看了该课程的syllabus，内容同样是AI时代的软件工程开发，但是斯坦福大学的课程在工具的介绍方面更加有广度。我们的课程应该只介绍了 trae，但是我看到斯坦福的课程要求大家提交作业至少要有两个工具生成的两个version，提到了很多AI工具，例如 cursor, claude code, replit, graphite，warp等等，覆盖编码，code review，cli等等多个方面。

然后就是本建议的重头戏，我想说明一下我的建议，有两个：

1. 如果项目内容必须关于网络开发，因为要使用林老师实验室的那个 webtestcopilot 的gui-agent 测试工具，那么我非常建议前端让助教来提供，这样究竟是vue还是react都不重要，后端统一 fastapi，约定好 API 文档和调用规范，这样大家开发都有比较好的参考，以及可以用大家熟悉的python
2. 彻底放弃web开发。web开发对于同学来说跨度偏大，哪怕我们统一技术栈共同学习 React 这种前端框架，但是 React 绝非可以直接上手的一个框架。还要至少三节课的时间来覆盖 html+css+js 以及甚至 typescript。js里面的Promise等等异步编程也是非常复杂的。因此我建议彻底放弃web 开发，用python开发一个有趣的项目，比如说利用python textual库莱开发一个 TUI 项目，例如 Git Client。为什么这个项目更好？首先就是这个项目是纯 python 语言的。

最后的最后，考虑到课程本身就是锻炼开发能力，那么我认为通过GitHub发布作业starter code等等是非常有必要的，每一次的

---

我们的课堂缺少练习，我能想到的一个比较好的方案是助教先提供一个需求文档和一个正确的程序，学生需要通过粗粒度的需求文档结合正确的程序作为参考，生成：

1. 完善的Acceptance Criteria
2. 或者一套完整的测试代码
3. 这个时候运行测试是通过的

助教再发布实现有问题的源代码，这个时候运行测试应该是测试不通过，并且应该能够借助测试来定位问题。假如测试直接通过，说明测试代码不够完善。

---

如果我们的课程划分成前1/3学习什么是网页开发，后2/3大家模仿一个网页开发，那么我觉得前期课程可以非常好的参考 gothinkster/realworld 这个仓库
