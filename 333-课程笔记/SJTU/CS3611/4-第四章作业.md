# Wireshark 实验：IP

在本实验中，我们将研究 IP 协议，重点关注 $\mathrm{IPv4}$ 和 IPv6 数据报。本实验分为三个部分。  
在第一部分，我们将分析由 traceroute 程序发送和接收的 $\mathrm{IPv4}$ 数据报跟踪文件中的数据包。  
在本实验的第二部分，我们将研究 IP 分片，在第三部分，我们将简要了解 $\mathrm{IPv}6$ 。

# 从 traceroute 执行过程中捕获数据包

为了为本实验的前两部分生成 IPv4 数据报的跟踪文件，我们将使用 traceroute 程序向gaia.cs.umass.edu 发送两种不同大小的数据报。

traceroute 的工作原理是首先发送一个或多个 IP 报头中生存时间（TTL）字段设置为 1 的数据报；然后向同一目的地发送一系列 TTL 值为 2 的数据报；接着向同一目的地发送一系列 TTL 值为 3 的数据报，依此类推。由于路由器必须将每个接收到的数据报中的 TTL值减 1。如果 TTL 值达到 0，路由器会向发送主机返回一个 ICMP 消息（类型 Ⅱ- TTL 超时）。

由于这种行为，一个 TTL 值为 1 的数据报（由执行 traceroute 的主机发送）会导致距离发送者一跳的路由器向发送者返回一个 ICMP TTL 超时消息；TTL 值为 2 的数据报会导致距离发送者两跳的路由器向发送者返回一个 ICMP 消息；TTL 值为 3 的数据报会导致距离发送者三跳的路由器向发送者返回一个 ICMP 消息，依此类推。通过这种方式，执行traceroute 的主机可以通过查看包含 ICMP TTL 超时消息的数据报中的源 IP 地址，了解自身与目的地之间路由器的 IP 地址。

我们运行 traceroute 并让它发送两种不同大小的数据报。两种数据报长度中较大的那个将要求 traceroute 消息被分片到多个 IPv4 数据报中。

Linux/MacOS 系统：使用 Linux/MacOS 的 traceroute 命令时，发送到最终目的地的 UDP 数据报的大小可以通过在命令行中目的地名称或地址后立即指定数据报中的字节数来显式设置。例如，要向 gaia.cs.umass.edu 发送 2000 字节的traceroute 数据报，命令如下：

traceroute gaia.cs.umass.edu 2000

Windows 系统：Windows 提供的 tracert 程序不允许更改 tracert 发送的 ICMP消息的大小。因此，无法使用 Windows 机器生成足够大以强制进行 IP 分片的ICMP 消息。但是，你可以使用 tracert 生成小的固定长度数据包来完成本实验的第一部分。在 DOS 命令提示符下输入：

tracert gaia.cs.umass.edu

如果你想完成本实验的第二部分，可以下载数据包跟踪文件（见提示 1）。
