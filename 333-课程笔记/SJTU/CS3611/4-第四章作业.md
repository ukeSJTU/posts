# 简答题

## 第一题

考虑互联3 个子网（子网1、子网2 和子网3）的一台路由器。假定这3 个子网的所有接口要求具有前缀`223.1.17/24`。还假定子网1 要求支持多达60 个接口，子网2 要求支持多达90 个接口，子网3 要求支持多达12 个接口。提供3 个满足这些限制的网络地址（形式为 a. b.c.d/x）

### 答案

先考虑子网2，因为它需要的接口最多。$2^{7}=128>90$，所以需要7位作为主机位。同理子网1: $2^6=64>60$，子网3: $2^4=16>12$。

所以：

- 子网2: `223.1.17.0/25`
- 子网1: `223.1.17.128/26`
- 子网3: `223.1.17.192/28`

## 第二题

考虑使用 32 比特主机地址的某数据报网络。假定一台路由器具有 4 条链路，编号为`0~3`，分组能被转发到如下的各链路接口：

| 目的地址范围                                                                 | 链路接口 |
| ---------------------------------------------------------------------------- | -------- |
| `11100000 00000000 00000000 00000000`到`11100000 00111111 11111111 11111111` | 0        |
| `11100000 01000000 00000000 00000000`到`11100000 01000000 11111111 11111111` | 1        |
| `11100000 01000001 00000000 00000000`到`11100001 01111111 11111111 11111111` | 2        |
| 其他                                                                         | 3        |

- a. 提供一个具有 5 个表项的转发表，使用最长前缀匹配，转发分组到正确的链路接口。
- b. 描述你的转发表是如何为具有下列目的地址的数据报决定适当的链路接口的。
  - `11001000 10010001 01010001 01010101`
  - `11100001 01000000 11000011 00111100`
  - `11100001 10000000 00010001 01110111`

### 答案

| 前缀                | CIDR            | 链路接口 |
| ------------------- | --------------- | -------- |
| `11100000 01000000` | `224.64.0.0/16` | 1        |
| `11100000 00`       | `224.0.0.0/10`  | 0        |
| `11100001 0`        | `225.0.0.0/9`   | 2        |
| `11100000`          | `224.0.0.0/8`   | 2        |
| `*`                 | `0.0.0.0/0`     | 3        |

- 对于`11001000 10010001 01010001 01010101`:
  1.  前16位不匹配
  2.  前10位不匹配
  3.  前9位不匹配
  4.  前8位不匹配
  5.  通配符匹配，转发端口3
- 对于`11100001 01000000 11000011 00111100`:
  1.  前16位不匹配
  2.  前10位不匹配
  3.  前9位匹配，转发端口2
- 对于`11100001 10000000 00010001 01110111`:
  1.  前16位不匹配
  2.  前10位不匹配
  3.  前9位不匹配
  4.  前8位不匹配
  5.  通配符匹配，转发端口3

# Wireshark 实验：IP

在本实验中，我们将研究 IP 协议，重点关注 IPv4 和 IPv6 数据报。本实验分为三个部分：

1. 在第一部分，我们将分析由 `traceroute` 程序发送和接收的 IPv4 数据报跟踪文件中的数据包;
2. 在本实验的第二部分，我们将研究 **IP 分片**;
3. 在第三部分，我们将简要了解 **IPv6**。

## 实验一：从 traceroute 执行过程中捕获数据包

为了为本实验的前两部分生成 IPv4 数据报的跟踪文件，我们将使用 **`traceroute`** 程序向 _`gaia.cs.umass.edu`_ 发送两种不同大小的数据报。

**`traceroute`** 的工作原理是首先发送一个或多个 IP 报头中生存时间（TTL）字段设置为 1 的数据报；然后向同一目的地发送一系列 TTL 值为 2 的数据报；接着向同一目的地发送一系列 TTL 值为 3 的数据报，依此类推。由于路由器必须将每个接收到的数据报中的 TTL 值减 1。如果 TTL 值达到 0，路由器会向发送主机返回一个 ICMP 消息（类型 II - TTL 超时）。

由于这种行为，一个 TTL 值为 1 的数据报（由执行 **`traceroute`** 的主机发送）会导致距离发送者一跳的路由器向发送者返回一个 ICMP TTL 超时消息；TTL 值为 2 的数据报会导致距离发送者两跳的路由器向发送者返回一个 ICMP 消息；TTL 值为 3 的数据报会导致距离发送者三跳的路由器向发送者返回一个 ICMP 消息，依此类推。通过这种方式，执行 **`traceroute`** 的主机可以通过查看包含 ICMP TTL 超时消息的数据报中的源 IP 地址，了解自身与目的地之间路由器的 IP 地址。

我们运行 **`traceroute`** 并让它发送两种不同大小的数据报。两种数据报长度中较大的那个将要求 **`traceroute`** 消息被分片到多个 IPv4 数据报中。

**Linux/MacOS 系统：** 使用 Linux/MacOS 的 **`traceroute`** 命令时，发送到最终目的地的 UDP 数据报的大小可以通过在命令行中目的地名称或地址后立即指定数据报中的字节数来显式设置。例如，要向 _`gaia.cs.umass.edu`_ 发送 2000 字节的 traceroute 数据报，命令如下：

```bash
traceroute gaia.cs.umass.edu 2000
```

**Windows 系统：** Windows 提供的 **`tracert`** 程序不允许更改 tracert 发送的 ICMP 消息的大小。因此，无法使用 Windows 机器生成足够大以强制进行 IP 分片的 ICMP 消息。但是，你可以使用 **`tracert`** 生成小的固定长度数据包来完成本实验的第一部分。在 DOS 命令提示符下输入：

```cmd
tracert gaia.cs.umass.edu
```

如果你想完成本实验的第二部分，可以下载数据包跟踪文件（见提示 1）。

执行以下操作：

1. 启动 **Wireshark** 并开始捕获数据包。（选择 “捕获” -> “开始”，或点击 Wireshark 窗口左上角的蓝色鲨鱼鳍按钮）。
2. 输入两条 **`traceroute`** 命令，以 _`gaia.cs.umass.edu`_ 为目的地，第一条命令的数据报长度为 56 字节。该命令执行完毕后，输入第二条 **`traceroute`** 命令，目的地相同，但数据报长度为 3000 字节。
3. 停止 **Wireshark** 跟踪。

### 问题 6

接下来，让我们查看从你的计算机通过 traceroute 发送到 `128.119.245.12` 的 UDP 段序列。你可以输入的显示过滤器是 `ip.src==192.168.86.61 and ip.dst==128.119.245.12 and udp and !icmp`。你的屏幕应该类似于图 2：

![image.png](https://pub-cc2ebc8a43754210aa734d07c4898ad1.r2.dev/2025/05/20250514201921828.webp)

在通过 traceroute 从你的计算机发送到 `128.119.245.12` 的这一系列 UDP 段所对应的 IP 数据报中，**哪些字段在不同数据报之间总是发生变化**？原因是什么？

#### 答案 6

1. **TTL (Time to Live)**：

   - 每组探测包的TTL值会递增（从1开始，然后2,3...）
   - 原因：traceroute的核心原理就是通过递增TTL值来发现路径上的每一跳路由器

2. **UDP目标端口**：

   - 从基准值`33435`开始递增
   - 原因：帮助区分不同的探测包，并使目标主机能够返回"端口不可达"的ICMP消息

3. **IP标识符(Identification)**：

   - 每个IP数据包都有唯一的标识符
   - 原因：用于可能的分片重组，确保每个数据包都可以被唯一识别

### 问题 7

在这一系列（包含 UDP 段的）IP 数据报中，**哪些字段保持不变**？原因是什么？

#### 答案 7

1. **源IP地址**：

   - 始终是发送`traceroute`命令的主机IP: `192.168.86.61`
   - 原因：确保ICMP回复能够返回到正确的发起方

2. **目标IP地址**：

   - 始终是`traceroute`的目标主机IP: `128.119.245.12`
   - 原因：我们探测的是到同一目的地的路径

3. **IP协议字段**：

   - 值为17（表示UDP）
   - 原因：`traceroute`使用UDP作为探测协议

4. **UDP源端口**：

   - 64928
   - 原因：简化回复匹配过程，便于识别属于同一`traceroute`会话的响应
