## 1. 分数占比

大作业分数占期末总评的30%。大作业内分数分为基础分+附加分两部分,基础分占比75%,附加分占比25%。基础分为必做内容的完成度,附加分为扩展内容的完成度,扩展内容鼓励多做,至少选做2项。

同学们自由组队,推荐为4-5人每组。本次大作业共10个题目,每个题目供2个组选择,选题链接模板: [https://kdocs.cn/l/cgXRMKXpbQnz](https://www.google.com/search?q=https://kdocs.cn/l/cgXRMKXpbQnz) (切勿覆盖他人已填表格!!!!!)。16周课上 poster 展示,现场打分。

主要分为两部分。

1. 项目海报。参照给出的学术会议 poster 形式,总结自己组的工作内容,制作一份海报。

# 题目一：基于SDN的虚拟网络拓扑构建与流表管理

## 实验目标

1. 掌握 SDN 架构的核心原理及OpenFlow 协议的基本操作;
2. 实践使用 Mininet 搭建网络拓扑并连接控制器(如Ryu或OpenDaylight);
3. 学习通过编程调用控制器 REST API 实现流表下发与管理;
4. 理解 VLAN划分与网络隔离的实现机制。

## 实验要求

### 1. 基础功能(必做)

#### 拓扑与控制器配置

- 使用 Mininet 创建包含至少2台交换机(支持 OpenFlow 1.3协议)和4台主机的拓扑,并保存为Python 脚本;
- 连接 Ryu 或 OpenDaylight 控制器,确保控制器能够识别拓扑中的交换机;
- 通过 ovs-ofctl 命令手动添加流表,实现以下通信规则:
  - h1与h3互通,h2与h4互通;
  - 其余主机间禁止通信。

#### 流表验证与测试

- 使用 pingall命令测试主机连通性,并通过Wireshark 抓包验证 VLAN 标签是否符合要求
- 查看交换机流表并截图记录(如ovs-ofctl dump-flows s1)。

### 2. 扩展功能(选做,任选2项)

- 自动化流表下发:编写 Python 脚本,在拓扑生成时自动下发流表(参考Ryu的 simple_switch.py 或OpenDaylight 的REST API);
- 动态网络控制:调用控制器 API 实现流表硬超时(如中断 h1-h3 通信20秒);
- 网络性能限制:在拓扑中为链路设置带宽、延迟、丢包率等参数(如h1与s1间带宽 10Mbps、延迟5ms);
- 胖树拓扑构建:编写 Python代码生成数据中心胖树拓扑,并验证多路径负载均衡。

## 技术栈要求

- 工具:Mininet、Ryu/OpenDaylight 控制器、Wireshark;
- 编程语言:Python (用于拓扑生成与API调用);
- 通信协议:OpenFlow;
- 数据存储:JSON文件(用于流表配置)。

## 分工建议

- 拓扑搭建(编写 Mininet 脚本并配置链路参数)1-2人
- 控制器开发(实现 Ryu/OpenDaylight的API调用)1-2人
- 流表管理(设计流表规则并验证通信隔离) 1人
- 测试与优化(压力测试及性能调优)1人

## 实验提交内容

1. 代码
   - Mininet 拓扑脚本(含性能限制代码);
   - 控制器 API调用程序(如流表下发脚本)。
2. 文档
   - 设计文档:系统架构图、流表规则定义(含VLAN 标记示例);
   - 测试报告:连通性测试截图、Wireshark 抓包分析;
   - 操作手册:环境配置步骤与脚本运行说明。
3. 演示
   - 实时展示拓扑生成与流表下发过程;
   - 模拟链路中断后流表重定向场景。

# 题目三：流式视频传输系统设计与码率自适应优化

## 实验目标

1. 掌握基于TCP的流式视频传输原理与分片封装技术;
2. 实现客户端与服务端的动态交互及视频实时播放功能;
3. 设计码率自适应算法(ABR)以应对网络波动;
4. 探索流式视频的高效路径优化与数据分片重组机制。

## 实验要求

### 1. 基础功能(必做)

#### 服务端功能

- 支持视频分片处理:将长视频分割为固定大小的片段(如每段5秒),封装为TS 格式文件;
- 基于TCP协议实现分片传输,支持并发处理多个客户端请求;
- 记录每个分片的发送时间与码率,并生成传输日志。

#### 客户端功能

- 动态请求视频分片:循环向服务端请求分片文件(如 ocean-1080p-8000k-0.ts),支持分片序号拼接;
- 接收分片后调用播放器库实现实时播放
- 本地缓存管理:将接收的分片临时存储至 download 文件夹,播放完成后自动清理。

### 2. 扩展功能(选做,任选2项)

- 码率自适应传输:根据网络带宽波动动态切换视频码率(如1080p→480p),需实现 ABR 算法并统计QoE(用户体验质量);
- 动态路径优化:集成学习算法优化传输路径,降低传输延迟并提升吞吐量;
- 滑动窗口流式处理:实现分片数据的滑动窗口重组机制,支持长视频流无缝播放;
- 端到端加密传输:使用AES加密视频分片,确保传输安全性。

## 技术栈要求

- 编程语言:C/Python(推荐C语言,与实验框架兼容);
- 通信协议:TCP(保证分片顺序与完整性),UDP可选用于状态监控;
- 工具库:FFmpeg(视频分片处理)、Wireshark(网络抓包分析);
- 数据存储:本地文件系统(分片存储)、SQLite (传输日志记录)。

## 分工建议

- 服务端开发(分片生成、并发传输与日志管理) 1-2人
- 客户端开发(分片请求、播放器集成与缓存) 1-2人
- 算法设计 (ABR算法实现与路径优化) 1人
- 测试与调优(网络波动模拟与性能分析) 1人

## 实验提交内容

1. 代码
   - 服务端与客户端完整源码(含分片处理与ABR算法实现);
2. 文档
   - 设计文档:系统架构图、分片协议格式、ABR 算法流程图;

# 题目四：DDoS攻击模拟与自动化防御系统设计

## 实验目标

1. 理解 DDoS攻击原理及常见攻击类型(如SYN Flood、HTTP Flood);
2. 掌握基于流量特征分析的攻击检测方法;
3. 实现基础防御策略(限速、黑名单、流量清洗);
4. 探索 AI 驱动的自动化攻击识别与响应机制。

## 实验要求

### 1. 基础功能(必做)

#### 攻击模拟模块

- 使用工具(如LOIC、hping3)模拟以下攻击类型:
  - SYN Flood:伪造随机源IP发送大量半连接请求;
  - HTTP Flood: 模拟合法用户发起高频 GET/POST请求;
  - UDP 反射放大攻击:伪造源IP向DNS/NTP服务器发送请求。
- 记录攻击流量特征(如包速率、协议分布、IP熵值)。

#### 防御系统模块

- 基于Linux 系统实现防御功能:
  - 流量限速:通过 iptables 限制单个IP连接速率(如每秒50个SYN包);
  - IP 黑名单:自动封锁异常IP(如1分钟内发起1000次请求);
  - 流量清洗:使用nftables 过滤非法协议包(如非HTTP端口的80请求)。

### 2. 扩展功能(选做,任选2项)

- 机器学习检测:使用Scikit-learn 训练流量分类模型(正常/攻击),特征包括包大小分布、协议比例;
- CDN 集成:配置 Nginx反向代理实现请求分发与源IP 隐藏;
- 自动化防御策略:编写 Python 脚本联动 Snort (IDS) 与 iptables 实现实时阻断;
- 隐蔽攻击识别:检测慢速攻击(如Slowloris)与加密流量 DDoS(如HTTPS Flood)。

## 技术栈要求

- 攻击工具:LOIC、hping3、Scapy(自定义攻击脚本);
- 防御工具:iptables/nftables、Snort、Nginx;
- 分析工具:Wireshark、Elastic Stack(流量可视化);
- 编程语言:Python(自动化脚本)、Bash(防火墙规则管理);
- 数据存储:MySQL/Redis(攻击日志记录)。

## 分工建议

- 攻击开发(模拟多种攻击类型并生成流量)1-2人
- 防御系统(配置防火墙规则与流量清洗策略)1-2人
- 流量分析(特征提取、攻击检测算法实现)1人
- 自动化模块(开发AI检测与实时阻断系统) 1人

## 实验提交内容

1. 代码
   - 攻击模拟脚本(Scapy 实现 SYN Flood 示例);
   - 防御规则配置文件(iptables/nftables 规则集);
   - 自动化检测程序。
2. 文档
   - 设计文档:系统架构图、攻击流量特征表、防御策略流程图;
   - 测试报告:攻击成功率对比(开启防御前后)、CPU/内存占用分析;
   - 操作手册:环境配置步骤与防御规则调试指南。
3. 演示
   - 实时展示攻击流量生成与防御系统拦截效果(Wireshark 抓包对比);
   - 模拟混合攻击(SYN+HTTP Flood)并触发自动化响应。

- 实时同步:使用WebSocket 实现多设备文件同步(如类似 Dropbox)。

## 技术栈要求

- 协议标准:HTTP/REST(上传/下载)、WebSocket(实时同步);
- 编程语言:Python (Flask/Django 框架)或Go (Gin 框架);

# 题目七：综述: Web3 技术的发展与未来

## 课题描述

Web3 作为互联网的第三代范式,以去中心化、用户主权和区块链技术为核心,正在重塑数字世界的经济、社会和技术架构。其核心特征包括数据所有权回归用户、智能合约自动化执行、跨链互操作性以及去中心化应用(dApps)的兴起。然而,Web3的发展也面临技术成熟度不足、监管政策多样化、安全风险频发等挑战。

## 基本要求

请综述阐述 Web3的底层技术(如区块链、智能合约、分布式存储、跨链协议)及其作用,对比Web1(静态网页)、Web2(中心化平台)与Web3 的技术差异,重点说明去中心化如何改变数据管理方式。

## 高级要求

1. 分析 Web3在以下领域的应用模式:
   - 去中心化金融(DeFi)
   - 数字身份与隐私保护
   - 去中心化自治组织(DAO)
2. 分析 web3可能存在的安全风险:列举2023年Web3领域安全事件(如私钥泄露、合约漏洞),总结损失规模与攻击手法。

## 其他要求

正文页数为8-10页,英文写作要求字体为 Times New Roman;中文写作要求字体为宋体。字号为小四,行距为1.2倍。页边距选择“适中”。引用采用尾注形式。报告末尾需附有各位组员明确的贡献度,由组员之间讨论决定。

# 题目八：去中心化P2P文件共享系统设计与优化

## 实验目标

1. 掌握 P2P网络架构的核心原理与节点发现机制;
2. 实现基于分布式哈希表(DHT)的资源定位与路由;
3. 设计高效文件分块传输与数据完整性验证机制;
4. 探索 NAT穿透技术(如STUN协议)与网络动态适应性。

## 实验要求

### 1. 基础功能(必做)

#### 核心模块

- 节点发现:实现节点注册与心跳机制,支持动态加入/离开网络(如Kademlia协议);
- 文件共享:将文件分块(如每块1MB)并支持多节点并行下载(类似BitTorrent);
- DHT 实现:构建分布式哈希表存储资源索引(Key=文件哈希,Value=节点 IP 列表);
- 数据验证:通过SHA-256 校验分块完整性,自动重传损坏块。

#### 通信协议

- 基于UDP 实现节点间通信(降低延迟);
- 自定义消息格式(需包含消息类型、TTL、分块序号等字段)。

### 2. 扩展功能(选做,任选2项)

- NAT穿透:集成STUN/TURN 协议实现内网节点直连;
- 加密传输:使用TLS 1.3 加密节点间通信;
- 动态负载均衡:根据节点带宽动态调整分块来源;
- 去中心化搜索:实现基于关键词的分布式搜索(如Gnutella 协议)。

## 技术栈要求

- 编程语言: Python (推荐 asyncio 异步库)或Java (Netty 框架);
- 协议标准:Kademlia DHT、BitTorrent 分块协议;
- 工具库:libp2p(节点通信)、bencode(编码解析);
- 网络模拟:Docker 容器模拟多节点环境。

## 分工建议

- 节点通信 (实现UDP通信与消息编解码) 1-2人
- DHT 开发 (构建 Kademlia 协议路由逻辑) 1-2人
- 文件管理 (分块处理、校验与并行下载) 1人
- 测试与优化 (NAT穿透实现与网络性能调优) 1人

## 实验提交内容

1. 代码
   - P2P 节点程序(含DHT与分块传输逻辑);
   - 文件分块工具(生成/合并分块文件)。
2. 文档
   - 设计文档:网络拓扑图、消息格式定义、DHT路由算法说明;
   - 测试报告:节点发现延迟、分块传输吞吐量对比(单源vs多源);
   - 用户手册:节点启动参数说明与故障排查指南。
3. 演示
   - 展示5个节点组成的网络,模拟文件分块下载过程;
   - 模拟节点离线场景,演示 DHT 自动路由修复。

# 题目九：NAT类型识别与穿透技术实现

## 实验目标

1. 掌握 NAT(网络地址转换)的工作原理及主要类型(Full Cone/Symmetric等);
2. 实现基于STUN协议的NAT类型检测与穿透方案;
3. 设计跨 NAT节点的P2P通信系统(TCP/UDP打洞);
4. 探索 NAT环境下的中继转发与负载均衡机制。

## 实验要求

### 1. 基础功能(必做)

#### NAT 环境搭建

- 使用 Mininet 或Linux Netfilter 模拟以下 NAT类型:
  - Full Cone NAT:任意外部IP/端口可访问映射端口;
  - Restricted Cone NAT:仅允许已知外部IP访问映射端口;
  - Port-Restricted Cone NAT:需匹配外部IP和端口;
  - Symmetric NAT:同一内网IP的不同会话分配不同公网端口。
- 记录不同 NAT 类型的行为特征(如端口分配策略、会话超时时间)。

#### 穿透实现

- 基于STUN 协议实现 NAT类型检测(客户端向STUN 服务器发起请求获取 NAT 信息);
- 实现 TCP/UDP 打洞:
  - UDP 打洞:客户端通过服务器交换地址信息后建立直连通道;
  - TCP 打洞:通过同时发起连接请求绕过NAT限制。

### 2. 扩展功能(选做,任选2项)

- 中继服务器:当直连失败时,通过TURN 服务器转发流量;
- 穿透成功率统计:在不同 NAT组合下测试穿透成功率(Symmetric Restricted);
- 动态负载均衡:根据网络状态自动选择直连或中继模式;
- IPv6 过渡支持:实现 NAT64/DNS64 环境下的穿透兼容。

## 技术栈要求

- 网络模拟: Mininet、Linux iptables (NAT规则配置);
- 协议工具:STUN 服务器(Coturn)、Wireshark(抓包分析);
- 编程语言:Python(推荐使用 socket 与 asyncio库);
- 数据存储:内存数据库(Redis 存储节点映射表)。

## 分工建议

- NAT 模拟 (配置不同 NAT类型并验证行为) 1-2人
- 穿透开发 (实现STUN 检测与打洞逻辑) 1-2人
- 检测服务 (搭建STUN/TURN 服务器与API接口) 1人
- 测试与优化(穿透成功率统计与性能调优) 1人

## 实验提交内容

1. 代码
   - NAT 模拟脚本(如Mininet 拓扑定义);
   - 穿透工具(支持TCP/UDP打洞);
   - STUN 检测客户端(输出NAT类型报告)。
2. 文档
   - 设计文档:NAT类型行为对照表、打洞协议流程图、负载均衡策略;
   - 测试报告:穿透延迟对比(直连vs中继)、不同NAT组合成功率;
   - 操作手册:实验环境配置步骤与穿透工具使用说明。
3. 演示
   - 展示 Full Cone与 Symmetric NAT间的UDP 打洞过程(Wireshark 抓包验证);
   - 模拟 NAT 类型动态变化场景(如Symmetric Cone)并触发重穿透。

# 题目十：手动实现DNS服务器与协议解析

## 实验目标

1. 掌握 DNS协议报文格式及核心记录类型(A/AAAA/CNAME/MX);
2. 实现递归查询与迭代查询的域名解析流程;
3. 设计 DNS缓存机制与TTL 过期策略;
4. 探索 DNSSEC签名验证与负载均衡(DNS轮询)的实现。

## 实验要求

### 1. 基础功能(必做)

#### DNS 服务器功能

- 报文解析:解析DNS请求报文(UDP53端口),提取查询域名与记录类型;
- 记录支持:至少支持A记录(IPv4)、AAAA记录(IPv6)、CNAME 记录(别名);
- 递归查询:向根域名服务器发起迭代查询,最终获取目标记录(需处理NS记录与 Glue 记录);
- 缓存机制:缓存查询结果并遵循TTL过期时间(如缓存命中时直接返回响应)。

#### 客户端功能

- 实现 DNS 查询工具:支持指定DNS 服务器发送查询请求(如dig @127.0.0.1 example.com A);
- 解析并输出 DNS 响应报文内容(包括Answer/Authority/Additional 部分)。

### 2. 扩展功能(选做,任选2项)

- DNSSEC 支持:验证 RRSIG 签名链(需集成RSA算法);
- 负载均衡:通过DNS轮询返回多个A记录(如 [www.example.com](https://www.example.com/) → 192.168.1.1, 192.168.1.2);
- 反向解析:实现PTR记录查询(IPv4/IPv6地址→域名);
- EDNS 扩展:支持扩展 DNS 报文大小与客户端子网信息(EDNS Client Subnet)。

## 技术栈要求

- 编程语言:Python (推荐 dnslib 库)或C(手动构造DNS报文);
- 协议标准:DNS RFC 1034/1035、DNSSEC RFC 4033;
- 工具库: Wireshark (抓包分析)、dig(测试工具);
- 数据存储: SQLite(缓存记录)、JSON文件(本地域名配置)。

## 分工建议

- 服务器开发(实现DNS报文解析与递归查询) 1-2人
- 客户端工具 (构建DNS 查询程序与响应解析) 1人
- 协议扩展(实现DNSSEC 或EDNS功能) 1人
- 测试与优化(缓存性能测试与超时重试机制)1人

## 实验提交内容

1. 代码
   - DNS 服务器源码(含缓存与查询逻辑);
   - 客户端查询工具(支持自定义记录类型);
   - 扩展功能代码。
2. 文档
   - 设计文档:DNS报文结构图、递归查询流程图、缓存淘汰策略;
   - 测试报告:查询延迟对比(缓存命中 vs 未命中)、负载均衡效果;
   - 用户手册:服务器配置说明(根服务器地址、缓存大小限制)。
3. 演示
   - 展示域名递归解析过程(Wireshark 抓包显示与根服务器交互);
   - 模拟缓存生效场景(相同域名二次查询响应时间显著降低)。
