## 课程安排 (Agenda)

- **CALL**: 介绍程序执行的四个核心阶段：**编译 (Compile)**, **汇编 (Assemble)**, **链接 (Link)**, **加载 (Load)** 。
- **编译器 (Compiler)**: 深入探讨编译过程的各个步骤 。
- **汇编器 (Assembler)**: 讲解如何将汇编代码转换为机器码，以及目标文件的格式 。
- **链接器 (Linker)**: 说明如何合并多个目标文件并解析它们之间的引用 。
- **加载器 (Loader)**: 解释可执行文件是如何被加载到内存中并运行的 。
- **程序翻译 vs. 解释 (Program Translation vs. Interpretation)**: 比较两种主要的程序执行方式 。

## CALL: 编译 (Compile), 汇编 (Assemble), 链接 (Link), 加载 (Load)

通常我们用`gcc foo.c`命令直接生成一个可执行文件`a.out`的过程，在口语中被称为“编译” (Compiling) 。实际上，这个过程包含了三个主要步骤，之后由加载器执行 。

1.  **编译 (Compile)**: 编译器 (Compiler) 将高级语言代码（如 C 语言的 `foo.c`）翻译成汇编语言代码 (`foo.s`) 。
2.  **汇编 (Assemble)**: 汇编器 (Assembler) 将汇编代码 (`foo.s`) 转换成机器语言模块，即目标文件 (`foo.o`) 。
3.  **链接 (Link)**: 链接器 (Linker) 将一个或多个目标文件（如 `foo.o` 和库文件 `lib.o`）合并成一个单独的可执行文件 (`a.out`) 。
4.  **加载 (Load)**: 加载器 (Loader) 将可执行文件从磁盘加载到内存中，准备运行 。

### 编译器 (Compiler)

- **输入**: 高级语言代码 (e.g., `foo.c`) 。
- **输出**: 汇编语言代码 (e.g., `foo.s` for RISC-V) 。
- **注意**: 编译器输出的汇编代码可能包含伪指令（pseudoinstructions），如 `mv`, `li`, `call`, `j` 等，这些伪指令会在后续步骤中被替换成真实的机器指令 。

### 汇编器 (Assembler)

- **功能**: 将汇编代码转换为二进制的机器码 。
- **输入**: 汇编语言代码 (e.g., `foo.s`) 。
- **输出**: 机器语言模块，即目标文件 (e.g., `foo.o`) 。
- **特点**: 汇编器会处理大部分指令，但对于需要其他文件信息的引用（如库函数 `printf`），它会将其延迟到链接阶段处理 。

### 链接器 (Linker)

- **输入**: 一个或多个目标文件 (e.g., `foo.o`, `lib.o`) 。
- **输出**: 一个可执行的机器码文件 (e.g., `a.out`) 。
- **优势**: 链接器支持**分离编译** (separate compilation)。这意味着如果你有多个源文件，修改其中一个文件时，只需要重新编译这一个文件，然后将生成的目标文件与其他未修改的目标文件重新链接即可，无需重新编译整个项目，大大提高了开发效率 。

### 加载器 (Loader)

- **输入**: 存储在磁盘上的可执行文件 (e.g., `a.out`) 。
- **输出**: 程序在内存中开始运行 。
- **过程**: 当你执行一个程序时，加载器（通常是操作系统的一部分）会负责将该程序的代码和数据从磁盘复制到内存中，并设置好初始状态，让程序开始执行 。

## 编译器 (Compiler) 详解

编译是将人类易于理解的高级语言转换为机器能够执行的低级语言的过程，这是 CALL 流程中技术上最具挑战性的一步 。

### 编译的步骤

1.  **预处理 (Preprocessing)**: 处理所有预处理器指令，例如 `#include` 和 `#define` 宏。这一步在严格意义上发生在编译之前，它会生成一个不含预处理指令的、完整的 C 代码文件 。
2.  **词法分析 (Lexical Analysis)**: 将源代码文本分割成一个个有独立语义的“词法单元” (tokens)。例如，`int main()` 会被分割成 `["int", "main", "(", ")"]` 。
3.  **语法与语义分析 (Parsing & Semantic Analysis)**: 分析词法单元序列的语法结构，以确定代码的准确含义。这通常通过构建一个**抽象语法树 (AST)** 来完成。例如，确定 `*` 符号是表示乘法还是指针解引用 。
4.  **优化 (Optimization)**: (可选) 对生成的中间代码进行改进，使其更有效率（运行更快或占用更少资源）。优化的级别可以通过编译器标志（如 `-O1`, `-O2`）来控制 。
5.  **代码生成 (Encoding)**: 将经过分析和优化的代码转换成目标汇编语言 。

### "Hello World" 编译示例

我们用下面的 C 代码来演示编译的全过程 ：

```c
#include <stdio.h>
#define ITERS 10
int main() {
    for(int i = 0; i < ITERS; i++)
        printf("Hello %s\n", "world");
    return 0;
}
```

1.  **预处理器**处理后，`ITERS` 被替换为 `10`，`#include <stdio.h>` 的内容（函数声明等）也被包含进来。代码变为 ：

    ```c
    // 内容来自 <stdio.h>
    int main() {
        for(int i = 0; i < 10; i++)
            printf("Hello %s\n", "world");
        return 0;
    }
    ```

2.  **词法分析器**将代码分割成词法单元 ：
    `int`, `main`, `(`, `)`, `{`, `for`, `(`, `int`, `i`, `=`, `0`, `;`, `i`, `<`, `10`, `;`, `i`, `++`, `)`, `printf`, `(`, `"Hello %s\n"`, `,`, `"world"`, `)`, `;`, `return`, `0`, `;`, `}`

3.  **解析器**构建抽象语法树来表示程序的结构 。

4.  **代码生成器** (Encoder) 最终输出 RISC-V 汇编代码 ：

    ```assembly
    .text
      .align 2
      .globl main
    main:
      addi sp, sp, -4
      sw   ra, 0(sp)
      li   t0, 10         # for 循环计数器 i 的等价物，初始化为 10
    Loop:
      beq  t0, x0, End    # 如果计数器为0，跳转到 End
      la   a0, str1       # 加载第一个参数 (格式化字符串) 的地址
      la   a1, str2       # 加载第二个参数 ("world") 的地址
      call printf         # 调用 printf 函数
      addi t0, t0, -1     # 计数器减 1
      j    Loop           # 跳转回 Loop
    End:
      lw   ra, 0(sp)
      addi sp, sp, 4
      li   a0, 0          # 设置返回值为 0
      ret                 # 从 main 函数返回
    .section .rodata
      .balign 4
    str1:
      .string "Hello, %s!\n"
    str2:
      .string "world"
    ```

## 汇编器 (Assembler) 详解

汇编器的主要任务是将汇编语言代码转换成二进制的机器码，并生成一个**目标文件** (`.o` 文件) 。

### 汇编过程

1.  **替换伪指令**: 将所有伪指令（如 `li`）转换成一条或多条真实的 RISC-V 指令 。
2.  **计算地址**:
    - **PC相对地址**: 对于分支 (`beq`) 和跳转 (`j`) 指令，如果目标标签在文件内部，汇编器可以计算出 PC（程序计数器）的相对偏移量。这通常需要**两遍扫描 (2-Pass Assembly)** ：
      - **第一遍**: 扫描整个文件，找到所有标签（如 `Loop`, `End`）的位置，并将它们记录在一个名为**符号表 (Symbol Table)** 的数据结构中 。
      - **第二遍**: 再次扫描代码，此时所有内部标签的地址都已知，汇编器可以计算出准确的跳转偏移量并生成机器码 。
    - **绝对地址**: 对于引用外部文件中的函数（如 `printf`）或静态数据（如 `str1`），汇编器在当前阶段无法知道它们的最终内存地址 。
3.  **生成目标文件**:
    - 汇编器将这些无法解析的引用记录在一个名为**重定位表 (Relocation Table)** 的特殊表格中，留给链接器后续处理 。
    - 最终生成的目标文件包含：代码段、数据段、符号表和重定位表等信息 。

### 汇编器指令 (Directives)

汇编代码中以 `.` 开头的不是指令，而是给汇编器的“指示” (Directives)，用于指导汇编过程 。

- `.text`: 声明后续内容为代码段 。
- `.data`: 声明后续内容为数据段 。
- `.globl main`: 声明 `main` 是一个全局符号，可以被其他文件引用 。
- `.string "..."`: 将一个字符串存储在数据段 。

### 目标文件格式 (Object File Format)

一个典型的目标文件（如ELF格式）包含以下部分 ：

1.  **文件头 (Header)**: 描述文件的整体结构，如其他部分的大小和位置 。
2.  **代码段 (Text Segment)**: 包含已翻译的机器指令 。
3.  **数据段 (Data Segment)**: 包含源文件中的静态数据（如全局变量和字符串常量） 。
4.  **符号表 (Symbol Table)**: 列出了该文件定义和需要引用的标签（函数名、变量名）。全局符号（如 `main`, `printf`）会被标记，以便链接器识别 。
5.  **重定位表 (Relocation Table)**: 一个“待办事项”列表，记录了代码中所有需要链接器在未来填写真实地址的位置 。
6.  **调试信息 (Debugging Info)**: 额外信息，帮助调试器将机器码映射回源代码行 。

## 链接器 (Linker) 详解

链接器的主要工作是将多个目标文件和库文件组合成一个单一的可执行文件 。

### 链接过程

1.  **合并段 (Segment Combination)**:
    - 将所有输入目标文件的代码段 (`.text`) 合并成一个大的代码段 。
    - 将所有数据段 (`.data`) 合并成一个大的数据段，并附加在代码段之后 。
2.  **解析引用 (Reference Resolution)**: 这是链接器的核心任务 。
    - 链接器为合并后的代码段和数据段分配最终的运行时内存地址（例如，代码段从 `0x00010000` 开始，数据段从 `0x10008000` 开始） 。
    - 它遍历每个目标文件的**重定位表** 。对于表中的每一项：
      - 它会在所有输入文件的**符号表**中查找该符号（如 `printf` 或 `str1`）的定义 。
      - 找到后，计算出该符号的最终绝对地址 。
      - 最后，用这个绝对地址“修补” (patch) 代码中需要重定位的位置 。

### 静态链接 vs. 动态链接

- **静态链接 (Static Linking)**:
  - 将库代码（如 `printf` 的实现）完全复制到最终的可执行文件中 。
  - **优点**: 可执行文件是自包含的，不依赖外部文件，便于分发 。
  - **缺点**: 如果库更新了（例如修复了一个bug），所有使用该库的程序都必须重新链接才能受益。同时，可执行文件体积较大 。
- **动态链接 (Dynamic Linking / DLLs)**:
  - 不将库代码复制到可执行文件中，而是在程序**加载时**或**运行时**才将程序与共享库（如 `.so` 文件）链接起来 。
  - **优点**: 节省磁盘空间和内存（多个程序可以共享同一个库的内存副本）。库升级方便，只需替换共享库文件即可 。
  - **缺点**: 增加了程序启动的开销和管理的复杂性 。

## 加载器 (Loader) 详解

加载器是操作系统的一部分，负责启动一个可执行文件 。

### 加载过程

1.  读取可执行文件的头部信息，以确定代码段和数据段的大小 。
2.  创建一个新的**地址空间** (address space) 给这个程序。这个空间包含了存放代码、数据和栈的区域 。
3.  将可执行文件中的代码和数据**复制**到新创建的地址空间的相应区域 。
4.  将命令行参数（如果有）复制到栈上 。
5.  **初始化寄存器**，特别是将栈指针 `sp` 指向栈的起始位置 。
6.  **跳转到程序的入口点**（通常是一个启动例程，该例程会调用 `main` 函数），程序正式开始执行 。

## 程序翻译 vs. 解释

执行一个源程序主要有两种方式：翻译和解释 。

- **解释器 (Interpreter)**: 一个直接读取源程序并执行其指令的程序。它逐行（或逐语句）分析并执行，不生成独立的目标代码。例如 Python 解释器 。
  - **优点**: 易于实现，错误信息更友好，平台无关性好 。
  - **缺点**: 执行效率通常比编译后的代码慢10倍以上 。
- **翻译器/编译器 (Translator/Compiler)**: 将源程序从一种语言完整地转换成另一种语言（通常是更低级的语言），生成一个新的程序文件。我们前面讨论的 C 语言编译过程就是典型的翻译 。
  - **优点**: 生成的代码运行效率高，性能好。可以隐藏源代码，有商业价值 。
  - **缺点**: 调试相对复杂 。

许多现代语言（如 Java）结合了两者：先将源代码编译成一种中间语言（字节码），然后在运行时由一个虚拟机（解释器）来执行这个字节码 。
