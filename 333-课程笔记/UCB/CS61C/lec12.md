## Direct-Mapped Caches

全相联（FA）缓存虽然灵活，但存在两个主要问题 ：

1.  **硬件复杂**: 需要大量的比较器和电路。为了确定是否命中，CPU必须将目标地址的Tag与缓存中**所有**块的Tag同时进行比较。
2.  **驱逐策略实现困难**: 像LRU这样的有效策略需要复杂的硬件来追踪每个块的访问历史。

用我们之前的**图书馆比喻**来说: 全相联缓存就像一个没有任何组织的书架，找一本书需要查看所有位置。这就导致实际过程中hit time也不够快。

**改进思路**:
我们不对整个书架进行搜索，而是将书进行**分组**。例如，A开头的书放在第一层，B开头的放在第二层。这样，找书时只需查看对应的那一小部分。这个“分组”策略在缓存中通过**索引 (Index)** 实现。

那么我们究竟该按照什么来进行分组，下面简单讨论一下每种设计的问题：

- No option that uses the data in the block will work
  - 因为我们需要先获得block才能访问data，所以我们分组的依据一定是只根据内存地址来决定的
- Top three bits of the tag: Doesn't distribute blocks well
  - 这是因为在实际的过程中，我么经常会使用连续的内存块，而这很大概率它们的top three bits是一样的
- Hashing is a nice "all-purpose" approach to distributing data into even groups, but it's not as good here
  - Adds extra computation time
  - Distributes blocks randomly, whereas we can get exactly even distribution
- Bottom three bits of the tag: Works well with consecutive blocks of memory
  - Also scales to arbitrarily many cache slots without much additional circuitry
  - 从技术角度上看，这也算是一种hashing算法，就是`tag % 8`
  - 这总方法也假定了我们number of groups一定是2的幂

##### 1.2 TIO地址分解与直接映射

我们将内存地址分解为三部分：**Tag, Index, Offset (TIO)**。

- **Offset**: 块内偏移，由块大小决定。
- **Index**: 决定了内存块能存放在缓存的哪个**组（或行）**。
- **Tag**: 用于在确定了Index后，验证该位置存放的是否是正确的内存块。

**如何选择Index位？**
我们选择地址中**紧邻Offset的低位比特**作为Index。这样做的好处是，连续的内存块（具有空间局部性）会被映射到不同的Index，从而均匀分布在缓存中，避免冲突。使用地址的高位比特作为Index效果会很差，因为连续访问的内存块高位比特往往相同，会导致它们全部映射到同一个Index，引发大量冲突。

##### 1.3 直接映射缓存定义与特性

**直接映射缓存 (Direct-Mapped Cache)** 是最简单的缓存结构，可以看作是“1路组相联”缓存。它的核心特点是：**每个内存块只能映射到缓存中的唯一一个特定位置（由其Index决定）**。

**工作流程**:

1.  根据内存地址的Index部分，直接定位到缓存中唯一可能存放该数据的位置。
2.  比较该位置的Tag与地址的Tag是否匹配，并检查有效位。
3.  如果匹配且有效，则命中；否则未命中。

**优缺点**:

- **优点**:
  - **电路简单**: 只需要一个比较器，因为Index已经确定了位置。
  - **速度快**: 结构简单，因此命中时间短。
  - **无需驱逐策略**: 每个Index只有一个位置，要替换时别无选择。
- **缺点**:
  - **冲突未命中 (Conflict Miss)**: 即使缓存有大量空闲空间，如果程序交替访问两个映射到**同一Index**的不同内存块，就会导致缓存**颠簸 (Thrashing)**，不断地驱逐和加载，导致命中率急剧下降。

**矩阵乘法示例**:
在直接映射缓存中运行矩阵乘法，如果矩阵A和B的起始地址导致`A[0]`和`B[0]`映射到同一个Index 0 ，那么在计算`C[0][0]`时，对`A[0]`的访问会加载其数据块，紧接着对`B[0]`的访问会将其驱逐，再访问`A[1]`时又会把B的数据块驱逐，如此反复。这导致了极低的命中率（示例中为50%）。

## N-way Set Associative Caches

#### 2. N路组相联缓存 (N-way Set Associative Caches)

为了在全相联和直接映射之间找到一个平衡点，我们引入了**N路组相联缓存 (N-way Set Associative Cache)**。

**定义**:
这种缓存将所有缓存块分成多个**组 (Set)**，每个组包含**N个块**。一个内存块的Index决定了它属于哪个组，但它可以被存放在该组内的**任何一个**位置（Way）。

- ** associativity (N)**: 每个组中的块数。
- 直接映射是 **1路 (1-way)** 组相联缓存。
- 全相联是 **M路 (M-way)** 组相联缓存，其中M是缓存的总块数。

**工作流程**:

1.  使用地址的Index找到对应的组。
2.  **并行**地将地址的Tag与该组中**所有N个块**的Tag进行比较。
3.  如果任意一个匹配且有效，则命中。
4.  如果未命中且该组已满，则需要使用LRU等驱逐策略在该组内选择一个块进行替换。

**优缺点**:

- **优点**: 显著减少了直接映射中的冲突未命中，提高了命中率，同时硬件开销（N个比较器）远小于全相联缓存。
- **缺点**: 电路比直接映射复杂，命中时间稍长。

**矩阵乘法示例**:
使用一个2路组相联缓存再次运行矩阵乘法，`A[0]`和`B[0]`现在可以共存于Index 0的组中，避免了颠簸。这使得命中率大幅提升（示例中达到75%） ，接近全相联缓存的性能。

## Miss Classifications

#### 3. Miss 分类 (Miss Classifications)

为了优化缓存设计，我们需要理解缓存未命中的原因。我们将未命中分为三类，即 "3Cs" ：

1.  **强制性未命中 (Compulsory Miss)**:
    - **定义**: 第一次访问一个数据块时发生的未命中。
    - **原因**: 这是不可避免的，因为数据最初不在缓存中。也称为“冷启动未命中”。即使是无限大、全相联的理想缓存也会有这种未命中。
    - **改进**: 增加块大小可以减少单位时间内强制性未命中的次数。

2.  **容量性未命中 (Capacity Miss)**:
    - **定义**: 由于缓存大小有限，无法容纳程序工作集所需的所有数据块而导致的未命中。
    - **原因**: 程序需要用到的数据总量超过了缓存的容量，导致之前加载的块被驱逐，之后又需要再次访问。
    - **改进**: 从硬件角度，增加缓存容量 ；从软件角度，优化算法，减小程序在一段时间内访问的数据总量（工作集）。

3.  **冲突性未命中 (Conflict Miss)**:
    - **定义**: 在直接映射或组相联缓存中，由于多个数据块被映射到同一个组（或位置），导致其中一个块被驱逐而发生的未命中。但在一个相同容量的全相联缓存中，这种未命中本可以避免。
    - **原因**: 缓存的相联度不足，导致“颠簸”。
    - **改进**: 增加缓存的相联度。

**注意**: 本课程为了简化，将所有非强制性未命中统称为**非强制性未命中 (Noncompulsory Misses)**，不再严格区分容量性和冲突性未命中。

## Multilevel Caches

#### 4. 多级缓存 (Multilevel Caches)

##### 4.1 动机与设计

单个缓存面临一个两难的权衡：为了追求高命中率，我们需要大容量缓存；但大容量缓存的访问时间（命中时间）会更长。

**解决方案**: 建立一个**多级缓存 (Multilevel Caches)** 体系。

- **L1 Cache**: 位于CPU核心上，容量最小（如几十KB），速度最快（访问延迟约1ns），每个核心独享。通常还分为指令缓存(L1i)和数据缓存(L1d)。
- **L2 Cache**: 容量比L1大（如几MB），速度稍慢，可能由少数几个核心共享。
- **L3 Cache**: 容量更大（如几十MB），速度更慢，通常由所有CPU核心共享。

**访问流程**:
CPU访问数据时，首先检查L1。如果L1未命中，则检查L2；如果L2也未命中，则检查L3；如果L3仍未命中，最后才访问主存。一旦在某一级缓存中命中，数据会同时被加载到它上面的所有更小、更快的缓存层中。

##### 4.2 多级缓存的AMAT计算

在多级缓存中，命中率和未命中惩罚的计算需要特别注意：

- **局部命中率 (Local Hit Rate)**: $L_i$ 缓存的命中率是指，在所有**到达** $L_i$ 缓存的访问中，命中的比例。
- **全局命中率 (Global Hit Rate)**: 在CPU发出的所有访问中，在 $L_i$ 缓存命中的比例。
- **命中时间**: 访问一个更深层级的缓存，其命中时间包含了访问其所有上层缓存并发现未命中的时间。例如，$L2$ 的命中时间 = (L1检查时间) + (L2检查时间)。

**AMAT 计算公式**:
$AMAT = T_{L1} + M_{L1} \times (T_{L2} + M_{L2} \times (T_{L3} + M_{L3} \times T_{Mem}))$
其中，$T_{Li}$ 是第i级缓存的命中时间，$M_{Li}$ 是第i级缓存的**局部未命中率**。

**示例**:
假设一个系统 ：

- L1: 命中时间 1ns, 命中率 50%
- L2: 命中时间 4ns, 命中率 75%
- L3: 命中时间 40ns, 命中率 80%
- 主存 (SRAM): 访问时间 80ns

**AMAT计算**:
CPU发出的访问中：

- 50% 的访问在L1命中，耗时 1ns。
- 50% 的访问在L1未命中，进入L2。
- 在这些访问L2的请求中，75%命中，占总访问的 $50\% \times 75\% = 37.5\%$，总耗时 $1ns + 4ns = 5ns$。
- 25%的L2访问未命中，进入L3，占总访问的 $50\% \times 25\% = 12.5\%$。
- ...以此类推。

用公式直接计算 ：
$AMAT = 1ns + 0.5 \times (4ns + 0.25 \times (40ns + 0.2 \times 80ns))$
$AMAT = 1ns + 0.5 \times (4ns + 0.25 \times (40ns + 16ns))$
$AMAT = 1ns + 0.5 \times (4ns + 0.25 \times 56ns)$
$AMAT = 1ns + 0.5 \times (4ns + 14ns)$
$AMAT = 1ns + 0.5 \times 18ns = 1ns + 9ns = 10ns$。

这个结果表明，多级缓存系统极大地降低了平均内存访问时间。

#### 5. 总结

缓存是现代计算机体系结构中至关重要的性能优化工具。通过理解不同的缓存设计（相联度、写策略、驱逐策略、多级结构）及其优缺点，硬件工程师可以选择最适合通用程序的参数组合 ，而软件工程师则可以编写出更具缓存效率的代码，从而最大化程序性能。

```text
直接映射 → 2-way → 4-way → 8-way → 全相联
    ↑                                    ↑
硬件简单                              硬件复杂
速度快                                速度慢
命中率低                              命中率高
功耗低                                功耗高
```
