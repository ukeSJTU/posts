# Go 语言中的声明语法

本文原文[链接](https://go.dev/blog/declaration-syntax)

## 引言

Go 语言的新手常常会疑惑为什么 Go 的声明语法与 C 语言家族的传统写法不同。在这篇文章中，我们将比较这两种方法，并解释为什么 Go 的声明会是现在这个样子。

## C 语言语法

首先，让我们谈谈 C 语言的语法。C 语言在声明语法上采用了一种不寻常但很巧妙的方式。它不是用特殊的语法来描述类型，而是通过写一个包含所声明项的表达式，并说明该表达式将具有什么类型。因此：

```c
int x;
```

声明 `x` 是一个 `int` 类型：表达式 '`x`' 将具有 `int` 类型。通常，要弄清楚如何写一个新变量的类型，可以写一个包含该变量的表达式，使其求值为一个基本类型，然后把基本类型放在左边，表达式放在右边。

因此，这些声明：

```c
int *p;
int a[3];
```

表明 `p` 是一个指向 `int` 的指针，因为 '`*p`' 具有 `int` 类型；而 `a` 是一个 `int` 数组，因 为 `a[3]`（忽略特定的索引值，该值被借用作为数组的大小）具有 `int` 类型。

函数呢？最初，C 语言的函数声明是把参数类型写在括号外面，像这样：

```c
int main(argc, argv)
    int argc;
    char *argv[];
{ /* ... */ }
```

同样，我们看到 `main` 是一个函数，因为表达式 `main(argc, argv)` 返回一个 `int`。在现代写法中，我们会写成：

```c
int main(int argc, char *argv[]) { /* ... */ }
```

但基本结构是一样的。

这是一个巧妙的语法想法，对简单类型来说效果很好，但很快就会变得令人困惑。最著名的例子是声明一个函数指针。按照规则，你会得到：

```c
int (*fp)(int a, int b);
```

这里，`fp` 是一个指向函数的指针，因为如果你写表达式 `(*fp)(a, b)`，你将调用一个返回 `int` 的函数。如果 `fp` 的一个参数本身就是一个函数呢？

```c
int (*fp)(int (*ff)(int x, int y), int b)
```

这开始变得难以阅读了。

当然，在声明函数时我们可以省略参数的名称，所以 `main` 可以声明为：

```c
int main(int, char *[])
```

回想一下 `argv` 是这样声明的：

```c
char *argv[]
```

所以你从它的声明中间删除名称来构造它的类型。不过，通过在中间放置名称来声明 `char *[]` 类型的东西并不是很明显。

看看当你不给参数命名时，`fp` 的声明会变成什么样：

```c
int (*fp)(int (*)(int, int), int)
```

不仅不清楚在

```c
int (*)(int, int)
```

中应该把名字放在哪里，甚至都不太清楚这是一个函数指针声明。如果返回类型是一个函数指针呢？

```c
int (*(*fp)(int (*)(int, int), int))(int, int)
```

这个声明很难看出是关于 `fp` 的。

你可以构造更复杂的例子，但这些应该足以说明 C 语言的声明语法可能带来的一些困难。

不过，还有一点需要说明。因为类型和声明语法是相同的，所以在解析中间有类型的表达式时可能会很困难。这就是为什么，例如，C 语言的类型转换总是要给类型加上括号，如：

```c
(int)M_PI
```

## Go 语法

C 语言家族之外的语言通常在声明中使用不同的类型语法。虽然这是一个独立的观点，但名称通常在前面，后面经常跟着冒号。因此，我们上面的例子变成了这样（用一个虚构但有说明性的语言）：

```
x: int
p: pointer to int
a: array[3] of int
```

这些声明很清晰，虽然有点冗长 - 你只需从左到右读。Go 从这里得到启发，但为了简洁起见，它去掉了冒号和一些关键字：

```go
x int
p *int
a [3]int
```

`[3]int` 的外观与如何在表达式中使用 `a` 之间没有直接的对应关系。（我们将在下一节回到指针。）你以牺牲单独语法为代价获得了清晰度。

现在考虑函数。让我们把 `main` 的声明按照 Go 的方式转写，尽管 Go 中的真实 `main` 函数不接受参数：

```go
func main(argc int, argv []string) int
```

表面上看这与 C 没有太大区别，除了从 `char` 数组改成了字符串，但它从左到右读起来很顺畅：

函数 `main` 接受一个 `int` 和一个字符串切片，并返回一个 `int`。

去掉参数名称后依然很清晰 - 它们总是在前面，所以不会有混淆：

```go
func main(int, []string) int
```

这种从左到右风格的一个优点是，当类型变得更复杂时，它仍然工作得很好。这是一个函数变量的声明（类似于 C 中的函数指针）：

```go
f func(func(int,int) int, int) int
```

或者如果 `f` 返回一个函数：

```go
f func(func(int,int) int, int) func(int, int) int
```

它仍然从左到右读起来很清晰，而且总是很容易看出哪个名字正在被声明 - 名字在前面。

类型和表达式语法的区别使得在 Go 中编写和调用闭包变得容易：

```go
sum := func(a, b int) int { return a+b } (3, 4)
```

## 指针

指针是印证规则的例外。注意在数组和切片中，Go 的类型语法把方括号放在类型的左边，但表达式语法把它们放在表达式的右边：

```go
var a []int
x = a[1]
```

为了保持熟悉感，Go 的指针使用了 C 的 `*` 符号，但我们不能为指针类型做类似的反转。因此指针是这样工作的：

```go
var p *int
x = *p
```

我们不能说：

```go
var p *int
x = p*
```

因为这个后缀 `*` 会与乘法混淆。我们本可以使用 Pascal 的 `^`，例如：

```
var p ^int
x = p^
```

也许我们应该这样做（并为异或选择另一个运算符），因为在类型和表达式上使用前缀星号会在很多方面使事情复杂化。例如，虽然可以写：

```go
[]int("hi")
```

作为类型转换，但如果类型以 `*` 开头，就必须加上括号：

```go
(*int)(nil)
```

如果我们愿意放弃 `*` 作为指针语法，这些括号就不需要了。

所以 Go 的指针语法与熟悉的 C 形式绑定在一起，但这种绑定意味着我们不能完全摆脱使用括号来消除语法中类型和表达式的歧义。

不过总的来说，我们相信 Go 的类型语法比 C 更容易理解，特别是当事情变得复杂时。

## 注释

Go 的声明从左到右读。有人指出 C 的声明是螺旋式的！参见 David Anderson 的 [顺时针/螺旋规则](http://c-faq.com/decl/spiral.anderson.html)。
