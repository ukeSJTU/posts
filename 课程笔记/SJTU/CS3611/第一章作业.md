# 简答题

## 第一题

请从两个角度（“构成描述”和“服务描述”）解释“什么是因特网”，并说明协议（protocol）在因特网中的作用。结合实例描述一种常见的网络应用及其依赖的协议栈。

### 答案

从“构成描述”的角度看，因特网是一个由通信链路和分组交换机连接大量端系统组成的一个世界范围的计算机网络。从“服务描述”的角度看，因特网是为各种分布式应用提供服务的联网基础设施。

协议在因特网中扮演着"通信规则"的关键角色，就像交通规则确保车辆有序通行一样。协议定义了网络中数据交换的格式、顺序和动作，确保不同设备之间能够正确理解和处理信息。

以网页浏览这个常见应用为例，当我们访问一个网站时，需要多层协议的配合：

1. 应用层使用HTTP/HTTPS协议，负责网页内容的请求和传输
2. 传输层的TCP协议确保数据可靠传输，处理丢包和重传
3. 网络层的IP协议负责数据包的路由和寻址
4. 链路层（如以太网或WiFi协议）处理实际的数据传输
5. 物理层负责比特流的传输

## 第二题

在分层体系结构中，TCP/IP 模型与 OSI 模型的主要区别是什么？请列举分层设计的两个优点和一个潜在缺点，并解释为什么现代网络更广泛采用 TCP/IP 模型而非 OSI 模型。

### 答案

TCP/IP模型和OSI模型的主要区别是：
1. OSI模型有7层（物理层、数据链路层、网络层、传输层、会话层、表示层和应用层），而TCP/IP模型通常有4层（网络接口层、互联网层、传输层和应用层）。  
2. OSI模型将应用层拆分为应用层、表示层和会话层三个独立层次，而TCP/IP模型将这三层功能合并到一个应用层。
3. TCP/IP模型有具体的协议实现（如IP、TC
4. P、UDP等），而OSI模型更多是概念性的框架。

分层设计的优点是模块化与独立性，每层只需要关注自己的功能，可以独立开发和优化；同时还提供了灵活的可拓展性，各层可以独立更新替换。而分层设计的缺点在于每一层都需要添加自己的头部信息，增加了数据包大小，并且跨层通信可能导致额外的处理延迟。

## 简要报告

### Wireshark如何体现协议分层

我们还是以上面的DNS查询响应结果为例：

```plaintext
Frame 128: 132 bytes on wire (1056 bits), 132 bytes captured (1056 bits) on interface en0, id 0
Ethernet II, Src: NewH3CTechno_7b:58:02 (54:c6:ff:7b:58:02), Dst: fa:1b:b6:af:c5:9c (fa:1b:b6:af:c5:9c)
Internet Protocol Version 4, Src: 202.120.2.101, Dst: 10.180.29.40
User Datagram Protocol, Src Port: 53, Dst Port: 61823
Domain Name System (response)
```

可以看到从上到下分别和我们学习的分层体系结构相匹配：

1. **物理层**：虽然Wireshark不直接显示物理层信号，但Frame信息（132字节）反映了物理传输的数据量
    
2. **数据链路层**：Ethernet II帧信息展示了MAC地址，确保数据在局域网内正确传递
    
    - 源MAC：54:c6:ff:7b:58:02（NewH3CTechno设备）
    - 目标MAC：fa:1b:b6:af:c5:9c
3. **网络层**：IPv4协议负责跨网络路由
    
    - 源IP：202.120.2.101（DNS服务器）
    - 目标IP：10.180.29.40（客户端）
    - 这一层处理数据包的路由选择和转发
4. **传输层**：UDP协议提供端口寻址功能
    
    - 源端口：53（标准DNS服务端口）
    - 目标端口：61823（客户端临时端口）
    - DNS选用UDP是为了减少开销，提高查询速度
5. **应用层**：DNS协议实现域名解析服务
    
    - 包含查询标识符、标志位、查询内容和应答记录

这种分层结构使得每层协议只需关注自身功能，无需了解其他层的实现细节，从而实现了模块化设计。当数据从应用层向下传递时，每层都会添加自己的头部信息；当数据向上传递时，各层会依次解析并移除相应头部，最终将纯应用数据交付给应用程序。

### DNS 查询 RTT 与理论传播时延的关系

理论传播时延主要受以下因素影响：

- **物理距离**：电磁波传播速度
- **网络拓扑**：中间路由器/交换机数量
- **网络负载**：网络拥塞状况

实际测量的 RTT 明显大于纯物理传播时延，这是因为实际 RTT 还包括：

- 路由器处理延迟
- DNS 服务器查询处理时间
- 队列延迟
- 可能的重传
